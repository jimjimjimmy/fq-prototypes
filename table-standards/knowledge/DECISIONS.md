# Decision Log — AG Grid Standardization

Running log of decisions made while scoping. Newest at top.

## 2026-07-08 — Scoping session (Benjamin + Claude)

- **D-001 · One engine, tiered profiles.** Don't fork "FlowUI table vs AG Grid." Standardize AG Grid so thoroughly (including a clean *simple* profile) that it becomes the default table primitive across all complexity levels. The decision becomes "which profile," not "which library."
- **D-002 · FlowUI Table = alternate P0.** Teams may keep using FlowUI Table for the simplest read-only cases. Anything more complex graduates to AG Grid. FlowUI Table is an off-ramp, not a competing standard — AG Grid is the gravity.
- **D-003 · Tiers are an additive capability ladder.** P0 display → P1 data-ops (filter) → P2 mutation (edit/aggregate) → P3 workflow/analytical. Dividing line is read vs write vs workflow. (Benjamin swapped filterable/manipulation: read-only filtering is simpler than mutation.)
- **D-004 · The top of the ladder branches, and both branches are treated the same.** P3a Workflow-complex (Recs/Checklist/Folders) and P3b Analytical-complex (Reporting/Variance) share the P0–P2 foundation; they differ only in their top capability class. Same design law, two mechanisms.
- **D-005 · Deliverable is staged.** Design standards first (align the team), then productize into a shared package. Standards become the spec the package implements.
- **D-006 · Phase 0 first slice = the rubric.** Ship the "default to the FloQast table, pick your profile" framework before tier work, to de-risk the org veto.
- **D-007 · Tracking = Confluence hub + Slack channel**, mirrored by an in-repo decision log (this file). **Confluence page placement decided:** Design **(DES)** space, new **top-level** page titled **"AG Grid Table Standards"** (cross-BU → not R2R/personal/journey-nested; design-led → not PROD). **PUBLISHED 2026-07-08** via twg → DES page **4678844741** (https://floqast.atlassian.net/wiki/spaces/DES/pages/4678844741/AG+Grid+Table+Standards). Source draft: `confluence-page.md`.
- **D-008 · AG Grid Enterprise — DECIDED.** The solution builds on AG Grid **Enterprise** (pivot, master/detail, sidebar, set/multi filter). For prototyping in this repo, the unlicensed **watermark is acceptable** (no key needed). This closes the license question the recs / reporting-optionality / table-settings PRDs were stuck on. (Formal procurement is an eng/business step, not a design blocker.)
- **D-009 · Horizontal-space stance (preference, not a hard rule).** *Prefer* solutions that fit vertically and avoid horizontal scroll — but it's a goal, not a never-break rule; some AG Grid tables will legitimately exceed page width. What we **harden**: key/priority data appears *before* any horizontal scroll (deliberate column ordering + pinned anchors), so scrolling only ever reveals secondary data. Mechanisms: workflow-complex contains width via master/detail; analytical-complex accepts width but tames it (pinned anchor + foldable column groups + compact density + drill-in-drawer).

- **D-010 · Prototype architecture = shared kit + showcase + ideations.** Common interaction patterns (filtering, saved-views, container chrome, cell renderers, theme) live in one shared `_kit/` consumed by everything. A single `showcase/` app runs all P0–P3b variations from that kit; individual `<area>-<date>/` ideations import the same kit and vary only the specifics. Patterns proven in an ideation get promoted back into the kit. Consistency by construction — no re-authoring common patterns per prototype. (See `WORKING.md`.)

- **D-011 · Ownership split — design+PM own strategy & prototypes; engineering hardens production.** This group (designers + PMs) owns the research, the consistent standardization strategy, the design, and the **prototype** implementation — targeted to complete **this quarter (Q3 2026)**. After that, **engineering teams harden the actual AG Grid implementation and standardize it consistently across all product features** (the production build). So: this group *decides and proves the strategy in prototypes*; engineering *builds, hardens, and standardizes it in production* downstream. The design-system team (Ariadne) is deprecated — no separate DS pipeline or intake.

- **D-012 · Kit + showcase BUILT (2026-07-09); stack matched to reuse, not the plan's v34.** The shared kit (`prototypes/src/_kit/`) + master showcase (all five profiles) are built and verified. Design Bar guidance is encoded in the kit: kill stacked headers, compact-by-default, right-align amounts/dates + left-align account numbers, master/detail over pivot-expand, summary counts over dashes, filters not in the right tool panel. **Stack:** React 18 + modular `@ag-grid-*@32` Enterprise + FlowUI 3.120.5, with `node_modules` symlinked to `recs-ag-grid` (no install — registry access uncertain). This diverges from the plan's unified v34/`AllEnterpriseModule` because reuse-via-symlink requires the packages actually present; capabilities are equivalent. `reporting-bu-q3`'s `agGridConfig` turned out to be patch-only (not runnable), so the pattern was reconstructed from `recs-ag-grid` + `ai-variance` + `fq-folders` + `admin-agent` + the accruals library. Run: `npm --prefix playspace/ag-grid-standardization/prototypes run dev` (:5190).

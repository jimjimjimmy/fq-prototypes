Connector Selection Flow

A single-screen picker showing every connector option on the same tier — pre-built systems (QBO, NetSuite, Sage Intacct, Salesforce, Workday) sit alongside custom transmission methods (File, API, SFTP) without status hierarchy. Built on the pattern from Kristin's original mockup, minus the "Which Data?" column.

Scope: entry → selection Coverage: pre-built systems · file · API · SFTP Pattern: single-screen picker, flat tier Compare: V2 (question-driven)

Framework: single-screen picker, all options equal

Every connector option appears on a single screen at the same level. No hierarchy, no de-emphasis, no escape hatches — the user sees everything available and picks what they want. Direct/CDC sources and custom transmission methods are siblings, not parent-child.

Group Options Notes
Pre-Built QBO, NetSuite, Sage Intacct, Salesforce, Workday, … Each presented with its system logo. Adds via source registry as new pre-built integrations come online.
Custom File (Manual Upload), API, SFTP Same tier as Pre-Built — no de-emphasis. Designed icons stand in for logos.

Pre-Built and Custom are visual groupings on the same tier — not a hierarchy. The screen shows both groups simultaneously, and every option within a group is an equal sibling.

The flow

Both first-time and returning users land on the same selection screen. All options are visible at once, grouped into Pre-Built and Custom. The two groups sit on the same tier — one is not subordinate to the other — and within each group every option is an equal sibling. Only QBO branches further (Basic vs. Enhanced) on a follow-up screen; everything else proceeds straight to its setup wizard.

Decisions to weigh

Structural choices made in the diagram above — each can be redirected.

1

QBO Basic vs. Advanced lives on a sub-screen, not on the main grid

Sub-screen Clean main list, room to explain the difference. Cost: one extra click for QBO users. (Drawn above.)
Two tiles Zero extra steps, but clutters the source list and forces users to understand the distinction up front without context.
Lean: sub-screen. The Basic/Advanced choice is consequential enough to warrant explanation.
2

Naming the QBO paths without surfacing Fivetran

"QBO Direct" / "QBO Sync+" are placeholders. Real candidates: Standard / Advanced, Direct / Real-time, API / Continuous Sync. The name has to convey why a user would pick one over the other — capability, freshness, and scope — without leaning on vendor names. Worth a separate naming pass.

3

Pre-Built and Custom as side-by-side groups on the same tier

All options live on one screen and the user sees everything at once. Pre-Built and Custom are presented as side-by-side groups — visually distinct but equal in status. Within each group, every option is a sibling.

Considered alternatives:

Single grid All options interleaved with no group labels. Most "flat" feeling. Rejected: File / API / SFTP feel out of place between QBO and NetSuite without context.
Sort order Single grid, ordered by usage / alphabetical / type. Rejected: implicit ranking that may not match intent, and it doesn't help users mentally categorize the options.
Chosen approach: grouped (reflected in the diagram above). Equivalent to Kristin's mockup pattern, with the second column ("Which Data?") deferred to the wizard.
4

Empty state and populated state diverge only in the entry CTA

First-timers get a hero / empty-state moment ("Connect your data" with explanation). Returning users get a quieter + Add Connector button. Both land on the same selection screen — same mental model, no separate first-run path.

5

Search / filter on the selection screen — deliberately omitted for v1

With ~8 options today, the grid is scannable in a glance. Once the option list crosses ~12, a search input at the top becomes worth adding. The framework supports it without restructure.

Open / future considerations

Flagging, not solving — out of scope for this pass:

  • Source unavailable / coming soon. Pattern for sources that are on the roadmap but not yet live.
  • Search-by-source-name. For when the source list grows past 10–12.
  • Other sources with Basic/Advanced paths. The QBO sub-screen pattern should be reusable when another source has equivalent multi-path complexity.
  • Categorization. If sources span ERPs, CRMs, HRIS, billing systems, etc., the grid may eventually need category groupings.

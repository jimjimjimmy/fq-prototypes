⚠️ Gaps & Open Questions

  • Open Q: Can a user have multiple SFTP connections (multiple usernames) under one account? If so, are they managed at the connector level or the dataset level?
  • Open Q: Is the sample file stored permanently or only for the duration of the wizard session?
  • Open Q: Can Close Upload be the sole long-term transport for a dataset, or is it expected to be a temporary bootstrap until SFTP is configured?
  • Open Q: If a dataset has both SFTP and Close Upload files landed, how does the system handle differing naming conventions between the two transport types?
  • Open Q: Can the transport type be changed after a dataset is configured (e.g. swap from Close Upload to SFTP once the pipeline is set up)?
  • Open Q: For SFTP credential rotation — if a password changes, where does the admin update it? Is there a connector management screen outside the dataset wizard?
  • Open Q: PGP/SSH UX specifics — does the admin paste a key, upload a file, or can a key pair be generated within the product?
  • Gap: No cancellation path defined — if the admin exits mid-wizard, is partial configuration saved as a draft or discarded?
  • Gap: No async/loading state defined for credential validation — what does the UI show while the system is checking SFTP credentials?
  • Gap: Permissions not defined — can any admin configure any connector, or is access scoped?

📌 Key Concepts

  • File Connector — The umbrella configuration that defines how a source file gets into Data Studio. Transport type (SFTP or Close Upload) is selected within the connector setup.
  • SFTP (Secure File Transfer Protocol) — Automated file delivery to an FQ-provided endpoint. Requires credential setup (username/password) and optionally PGP encryption and/or SSH keys.
  • Close Upload — Manual file delivery through the FloQast UI. No credential setup required. Treated identically to SFTP after delivery — still requires file naming pattern, accounting period config, and entity config.
  • Sample File — A file uploaded manually when no pipeline files have landed yet. Dual-purpose: used for schema definition during wizard setup AND available as a test data source in Field Mapping (Test with Sample Data vs Test with Real Data).
  • File Naming Pattern — A pattern (e.g. regex or token-based) that the system uses to identify which incoming files belong to this dataset. Required for both SFTP and Close Upload since both are recurring delivery methods.
  • Accounting Period Config — Defines how the system derives which accounting period an incoming file belongs to — from the filename or from a column inside the file. Cannot be inferred from transport type alone. Changes to this step are covered in a separate PRD — out of scope here.
  • Entity Config — Defines how the system identifies which FloQast entity each row or file belongs to. Cannot be inferred from transport type alone. Changes to this step are covered in a separate PRD — out of scope here.
  • Schema Definition — The process of inferring column names and data types from a source file. Admin reviews and confirms before proceeding. Changes to this process are covered in a separate PRD — out of scope here.
  • PGP Encryption — Optional file encryption layer for SFTP. Admin provides a public key; the sender encrypts files before delivery.
  • SSH Key — Optional authentication method for SFTP connections as an alternative or supplement to username/password.

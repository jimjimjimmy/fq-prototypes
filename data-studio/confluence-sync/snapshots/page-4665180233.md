# 1. Objective

This sub-PRD defines the Data Studio product requirements for the SAP S/4HANA Private Cloud prebuilt connector. It covers the end-to-end setup experience a FloQast implementor or CS team completes to connect a customer's SAP S/4HANA Private Cloud environment to FloQast via SFTP, including connector selection, SFTP provisioning, entity mapping, and auto-configuration of data models and mappings. It does not cover the SAP-side ABAP transport installation, job scheduling, or Basis configuration, which are defined in the SAP Integrations Master PRD and its sub-PRDs.

The primary users of this flow are FloQast implementors and CS teams setting up new SAP S/4HANA Private Cloud customers in Data Studio. In some cases, a customer's IT or Basis team may complete steps in collaboration with the FloQast team.

S/4HANA Private Cloud shares the same customer-managed transport and SFTP delivery model as SAP ECC, but uses different underlying SAP data sources — notably ACDOCA as the universal journal in place of ECC's BKPF/BSEG/FAGLFLEXT tables. This means the connector type, file types, and mappings are distinct from ECC and must be configured separately, even though the Data Studio setup experience is substantially similar. File naming conventions and expected file types are pre-established by FloQast in collaboration with ActionFI and are known at connector setup time — no customer-specific input is required beyond completing the SFTP provisioning and entity mapping steps.

A successful S/4HANA Private Cloud setup through Data Studio means that once a customer's ABAP connector is installed and scheduled, files arrive at FloQast's SFTP server, are automatically recognized as S/4HANA Private Cloud data (and correctly disambiguated from SAP ECC files), and flow through to downstream FloQast products without additional configuration work.

# 2. Key Benefits

* **Distinct connector for S/4HANA Private Cloud:** S/4HANA Private Cloud appears as its own named, icon-labeled connector — separate from SAP ECC — reflecting the different underlying data model and ensuring correct auto-configuration.

* **Zero file configuration required:** Because naming conventions are pre-established with ActionFI, implementors do not need to configure individual files or provide sample file names — setup is driven entirely by connector type selection.

* **Auto-configured models and mappings:** Standard data models for accounts, balances, GL transactions (ACDOCA-based), FX rates, subledger transactions, companies, and dimensions are created automatically at connection setup.

* **Auto-configured dimensions:** Dimension file definitions are auto-created based on the known S/4HANA Private Cloud extract structure.

* **Reduced Engineering involvement:** CS and implementation teams can onboard new S/4HANA Private Cloud customers without manual Engineering intervention.

* **Visibility into configuration:** After setup, implementors can view all auto-created models and mappings directly in Data Studio to validate and review.

* **Extensible for custom fields:** Additional fields in a customer's extract can be added and configured through the standard file workflow edit experience.

* **Platform-native integration:** Once connected, S/4HANA Private Cloud data flows through Data Platform 2.0 and is available to all downstream FloQast products.

# 3. Use Cases

1. A FloQast implementor navigates to Data Studio, selects SAP S/4HANA Private Cloud from the prebuilt connector list, completes the SFTP provisioning steps and entity mapping within the wizard, and finishes setup — at which point Data Studio auto-configures the expected data models, mappings, and dimensions without any additional steps.

2. After completing connection setup, a FloQast implementor navigates to the connection in Data Studio and reviews the auto-created models and mappings to confirm they correctly reflect the customer's S/4HANA account structure before the first file is processed.

3. A customer's Basis team has configured SAP S/4HANA Private Cloud to deliver files to the FloQast SFTP endpoint on a nightly schedule. Data Studio recognizes the incoming files based on the pre-established naming convention and routes them correctly.

4. A FloQast CS team member checks the connection status in Data Studio and confirms that files have been received and processed successfully after the customer's first scheduled SAP job run.

5. A customer's S/4HANA Private Cloud environment includes custom fields in their ACDOCA-based extract. A FloQast implementor uses the standard file workflow edit experience to add and configure those custom fields.

6. FloQast (system) receives a file on the SFTP server and correctly identifies it as belonging to an S/4HANA Private Cloud connection — rather than an ECC or generic SFTP connection — based on the pre-established naming convention, and routes it through the correct pipeline.

# 5. Assumptions

 1. Customers are on SAP S/4HANA Private Cloud and have the FloQast ABAP transport installed and configured by their Basis team prior to completing Data Studio setup.

 2. File delivery to FloQast is via SFTP. The SAP-side SFTP configuration (destination, credentials) is handled by the customer's Basis team outside of this flow.

 3. S/4HANA Private Cloud uses ACDOCA as the primary universal journal source (vs. BKPF/BSEG/FAGLFLEXT in ECC). Mappings and models must reflect this difference.

 4. A standard set of file types is expected from every S/4HANA Private Cloud connection (accounts, balances, GL transactions, FX rates, subledger transactions, companies, dimensions). The exact list is \[TBD pending ActionFI tech spec\].

 5. File naming conventions for S/4HANA Private Cloud extracts are pre-established by FloQast in collaboration with ActionFI. They are distinct from ECC naming conventions and can be used to route files correctly. Customer input is not required to define or confirm these conventions during setup.

 6. Auto-detection of S/4HANA Private Cloud files vs. ECC and generic SFTP files is technically feasible and will be defined in collaboration with ActionFI.

 7. Volume handling behavior (append, period replace, or full history) for each file type is defined and consistent across S/4HANA Private Cloud customers. \[TBD — to be confirmed with ActionFI.\]

 8. The standard file workflow edit experience is sufficient to support custom field configuration without changes to the core setup flow.

 9. Data Platform 2.0 is available and able to ingest and normalize S/4HANA Private Cloud extract files.

10. The frequency at which SAP delivers files is configured entirely within SAP and is not managed or set in Data Studio.

# 9. User Interaction and Design

Prototype: \[TBD\]

## Connector Selection

The Data Studio prebuilt connector section displays a tile for SAP S/4HANA Private Cloud alongside other prebuilt connectors, visually differentiated from the SAP ECC tile. Clicking it begins the S/4HANA Private Cloud connection setup wizard.

## SFTP Setup Step

The user is walked through the standard SFTP provisioning flow. The system provisions SFTP credentials and displays the endpoint details (host, port, username, password or key) for the user to copy and share with the customer's Basis team. This step is functionally identical to the standard SFTP setup flow. No file naming input is requested at any point in the wizard.

## Entity Mapping Step (Within Wizard)

Immediately following SFTP setup, the wizard presents the entity mapping step. The implementor assigns the customer's FloQast entities to the connection. This step is required to complete the wizard. The connection is not activated until entity mapping is confirmed.

## Auto-Configuration on Completion

When the implementor confirms the connection, the system automatically applies the pre-established S/4HANA Private Cloud naming conventions, creates the expected file type configurations, and generates all standard data models (accounts, balances, GL transactions sourced from ACDOCA, FX rates, companies, subledger transactions), field mappings, and dimension definitions in the background. The user sees a confirmation state indicating setup is complete and the connection is active and ready to receive files. Models and mappings reflect the S/4HANA ACDOCA structure, not ECC's.

## Post-Setup Model and Mapping Review

After setup, the implementor can navigate to the connection in Data Studio and view all auto-created models and their field mappings. This uses the standard model/mapping UI. The implementor can use this view to validate the configuration or identify any custom fields that need to be added via the file workflow edit experience.

## Connection Management / Editing

Once active, the connection can be viewed and edited. Custom fields can be added to any auto-configured model through the standard file workflow edit experience. Standard SFTP connection management (disable, delete, credential rotation) applies.

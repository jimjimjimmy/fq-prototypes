## Objective

This sub-PRD defines the standard data mapping layer for the QuickBooks Online (QBO) integration within the FloQast Data Platform. When a user establishes a QBO connection, FloQast automatically provisions a standard mapping that governs how QBO data flows from the QBO REST API v3 or Fivetran into FloQast's normalized data models. This eliminates manual configuration as a prerequisite for first sync and ensures a consistent, validated starting point for every new connection.

Users can choose to use the standard mapping as-is or opt into customization, where they can edit endpoint parameters and field-level mappings for their specific realmId. At any point, they can reset to the FloQast-managed standard. This document covers the standard mapping schema, auto-provisioning behavior, customization mechanics, and the field-level mapping definitions for both ingestion paths.

## Key Benefits

1. Zero-config start: standard mapping is auto-provisioned on connection setup, enabling immediate sync without manual field configuration.
2. Consistent data foundation: all QBO connections begin from the same validated mapping, reducing data quality issues caused by misconfiguration.
3. Flexibility without friction: users can customize endpoint parameters and field mappings without engineering involvement, while staying within a guardrailed UI.
4. Dual-path normalization: mappings are defined for both the QBO REST API path (accounts + balances) and the Fivetran path (accounts + transactions), ensuring FloQast's data models are populated consistently regardless of ingestion method.
5. Safe reversion: users can always reset to the standard mapping if customizations cause issues, without losing historical sync data.

## Use Cases

* A new SMB customer connects their QBO account to FloQast. The standard mapping is automatically created on connection setup, pre-configured for the API path (accounts + balances). The customer can begin syncing immediately with no additional steps.
* A mid-market customer wants to adjust which QBO fields are included in their account mapping. They navigate to integration settings, switch from Standard to Custom mode, and edit field mappings to reflect their chart of accounts structure.
* A CAS firm admin sets up QBO connections for multiple client entities. Each realmId receives its own independent standard mapping instance. The admin customizes the mapping for one client without affecting any others.
* A customer using the Fivetran path reviews their transaction mapping to verify that GL lines are flowing into the correct FloQast fields before enabling the AI Variance workflow.
* A customer who previously customized their mapping encounters a sync error they cannot trace. They reset to the standard mapping from the integration settings page, restoring the FloQast default without losing prior synced data.

## Assumptions

1. The standard mapping is connection-scoped: each QBO connection (realmId) receives its own mapping instance.
2. The API path supports accounts and balances only (via the QBO REST API v3 Trial Balance and Accounts query endpoints). GL transactions are not supported via the API path.
3. The Fivetran path supports accounts and transactions. Balances are not ingested separately via Fivetran; the trial balance aggregation logic will be implemented based on Fivetran data in a balance service outside of this scope
4. Balance values are not returned directly by the QBO API - they must be computed by aggregating the Trial Balance report: balance = debit_amount - credit_amount, applied at the account level.
5. The standard mapping is auto-provisioned at the moment a QBO connection is successfully established (post-OAuth completion). No user action is required.
6. Customization is opt-in. The standard mapping is the default for all new connections and can always be restored via a Reset to Standard action.
7. The standard mapping covers only the fields required to populate FloQast's core data models. Additional or non-standard endpoint fields are handled in Data Studio (separate sub-PRD).
8. Standard mapping templates are maintained by FloQast. When FloQast updates a standard template, existing connections on the standard mapping are not automatically updated (update behavior is out of scope for v1).
9. QBO REST API v3 remains the stable API surface. Intuit field names and response schemas are assumed stable for the duration of development.

## Milestones

1. **Phase 1:  Standard Mapping Schema Definition:** Define and document all field-level mappings for the API path (accounts + balances) and the Fivetran path (accounts + transactions). Finalize the balance aggregation logic and confirm Fivetran table/column names. Produce the canonical standard mapping schema that serves as the source of truth.
2. **Phase 2: Auto-Provisioning:** Implement automatic standard mapping creation triggered by successful QBO connection setup. Mapping is scoped to the connection's realmId. Validate provisioning across both API and Fivetran paths. Handle failure states with retry logic.
3. **Phase 3: Mapping Visibility:** Surface the current mapping in the integration settings UI, showing source fields, target fields, and transformation notes.
4. **Phase 4: Customization:** Enable opt-in customization of endpoint parameters and field-level mappings. Implement the Reset to Standard capability.

## User interaction and design

**Standard Mapping Auto-Provisioning (Connection Setup)**

When a user completes the QBO OAuth flow and connection setup, the system silently provisions the standard mapping in the background. No user action or confirmation is required. The user sees a success state confirming their connection is established and ready to sync.

‌

The connection type selected during setup (API vs. Fivetran) determines which standard mapping template is applied:

* API path: standard accounts + balances mapping is provisioned.
* Fivetran path: standard accounts + transactions mapping is provisioned.

‌

If provisioning fails, the user is shown an error state with a retry option. The connection itself is not invalidated — the user can retry mapping provisioning without restarting the OAuth flow.

‌

**Mapping Configuration View (Integration Settings)**

Accessible from the integration settings page for the QBO connection. The view contains:

* For Standard mode: a banner stating this is the FloQast-managed default mapping.
* When a user creates a new version from here, an informational prompt explains they are creating an editable copy of the standard mapping for this connection.
* A "Reset to Standard" button is always visible for custom mappings. Clicking it opens a confirmation modal: "This will replace your custom mapping with the FloQast default. Your previously synced data will not be affected." The user must confirm before the reset is applied.

**Edge Cases**

* If a required FloQast target field has no valid source field selected, an inline validation error is shown and the user cannot save until it is resolved.
* If the standard mapping template is updated by FloQast after a connection has already been provisioned, the existing connection's mapping is not automatically updated (behavior to be defined in a future iteration).
* CAS firm admins managing multiple realmIds can only edit the mapping for one connection at a time; there is no bulk mapping update in v1.

## Out of Scope

* Data Studio custom endpoint configuration: the ability to add non-standard QBO endpoints is covered in a separate sub-PRD.
* FX Rates and Companies data model mappings: not included in the standard mapping for v1.
* GL Transactions via the QBO REST API: transactions are Fivetran-only in this release.
* Automatic propagation of standard mapping updates to existing connections: if FloQast updates its standard template, connections already on standard mode are not auto-updated in v1.
* Bulk mapping management across multiple realmIds: CAS admins must update mappings per connection in v1.
* Write-back or bi-directional sync: FloQast is read-only from QBO.
* Non-QBO ERP integrations: governed by separate PRDs.
* QBO Desktop: this sub-PRD targets QBO Online only.

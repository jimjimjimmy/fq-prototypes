## 🎯 Objective

Today, customers whose data providers deliver data across multiple files have no self-service path to combine them in Data Studio. Joining datasets requires engineering intervention — custom scripting that is slow, hard to maintain, and doesn't scale as the customer base grows.

This PRD defines the Dataset Linking capability in Data Studio: a guided, no-code interface that allows admins and implementation team members to define how two or more source datasets connect — specifying the join key between them — without writing SQL or opening a support ticket.

## 🔤 Definitions & Terms

For all terms used in this PRD, see the shared [Definitions & Terms (Data Studio)](https://floqast.atlassian.net/wiki/spaces/Data/pages/4464869409) page. Key terms relevant to this PRD: **Join Key**, **Linked Dataset**, **Primary Dataset**, **Grouped Datasets**.

## 🏅 Why This Is Important

FloQast's Data Platform 2.0 is built to scale — but until now, each Model has been constrained to a single source dataset. For customers whose data providers deliver data across multiple files, combining those sources has required engineering intervention.

Dataset Linking removes that constraint. By giving admins a self-service interface to define how datasets relate to one another, FloQast can support a broader range of customer data configurations without engineering involvement.

## 💡 Key Benefits

1. **Self-service for admins and implementation teams**
2. **Flexibility on the source side**
3. **Greater data breadth for downstream products**
4. **Scales with customer complexity**

## ✅ Use Cases

| # | Persona | Scenario | Expected Outcome |
| --- | --- | --- | --- |
| 1 | Admin / Implementation Team | Customer delivers GL transactions in one file and a "Transaction Types" file separately each period. | Admin links both datasets, selects join key on each side. |
| 2 | Admin / Implementation Team | The join key exists as a single column in one dataset, but in the other it is split across two columns. | Admin defines a concatenated join key expression. |
| 3 | Admin / Implementation Team | The join relationship requires matching multiple columns simultaneously — a composite key. | Admin selects multiple fields on each side to form a composite join key. |
| 4 | Admin / Implementation Team | Join key values don't align — e.g., one uses numeric IDs and the other uses string codes. | The linking UI surfaces a preview showing unmatched rows. |
| 5 | Admin / Implementation Team | Customer's linked Model is configured and published. AI Variance consumes the Model's output. | AI Variance receives a wider set of fields from the combined dataset. |

## 🤔 Assumptions — Established

1. Admins and FloQast implementation teams are the only users who configure dataset linking.
2. The linking UI abstracts all join logic — users select fields from dropdowns. Raw SQL is not exposed.
3. Connectors must be configured and datasets available in Data Studio before linking can be configured.
4. A Model with multiple Linked Datasets must have exactly one Primary Dataset designated.
5. Concatenated and composite join keys are in scope.
6. Linking is always primary-anchored.
7. Left join and inner join are supported in v1.

## 🗺️ Scope

### In Scope

* Dataset linking for Models across all connector types
* Simple join key definition
* Composite join keys
* Concatenated join keys
* Admin-selectable join type: left join and inner join
* Preview of linking output in the UI
* Support for linking two or more Linked Datasets
* AI-assisted join key suggestion

### Out of Scope

* Additional join types beyond left and inner
* End-user configuration
* Raw SQL access
* Global Dimensions
* Grouped Dataset configuration (covered in Model Creation 1 of 4)
* Write-back / bi-directional sync

## 🎨 UX Requirements

### Source Datasets Tab — Linking Entry Point

The "Link Datasets" button appears on the Source Datasets tab once the user has added a qualifying combination of datasets. After a linking configuration is saved, the join type label is displayed next to the Primary Dataset.

### Link Datasets Modal

The modal handles: simple join key selection, composite join keys, concatenated join keys, join type selection via plain-language options, and system-suggested join key.

Prototype: [Source Datasets — Linking and Grouping](https://www.figma.com/make/shPr2fQIIEGWp7zqV8oZCp/Source-Datasets---Linking-and-Grouping?t=9paoCvzG7wTVEgyS-1)

## 🔍 Gaps

1. **Right join and full outer join** — deferred to future release.
2. **Linking configuration in versioning** — unclear how changes interact with Model versioning.
3. **Linking validation in the pipeline** — not specified how join errors are handled downstream.
4. **Suggested join quality feedback** — no mechanism for admins to provide feedback on suggestions.
5. **Non-admin visibility into linking configuration** — not defined.

## 🎯 Objective

This PRD defines requirements for multi-entity grouping in Entity Scope configuration within Data Studio. When multiple entities share the same source file — same headers, same accounting period, same file — admins should be able to represent them as a single grouped definition rather than one row per entity. This applies to all file types in Data Studio, including Chart of Accounts, balance, and dimension files. It reduces connector source clutter, accurately reflects the underlying data model, and ensures the source data view for a model surfaces one row per grouped definition rather than one row per entity.

## 💡 Key Benefits

* Eliminates redundant source rows for shared files, giving admins and end users a cleaner, more accurate view of connector data sources.

* Selecting "All Entities" creates a single grouped definition, reducing setup steps for the common case.

* Multi-select entity targeting gives admins precise control when a definition should cover a subset of entities.

* Overlap detection flags structurally identical definitions before they create duplicate sources.

* Applies uniformly across all file types — including dimension files — so the behavior is consistent throughout Data Studio.

## ✅ Use Cases

* **Shared COA file, all entities:** An admin sets up a connector for a Chart of Accounts file that applies to all entities. They select "All Entities" in the Entity Scope tab. The system creates one grouped definition. The connector shows one source row, and the source data view for the Accounts model shows one row for that definition.

* **Shared dimension file, subset of entities:** An admin selects three specific entities for a dimension file definition. The grouped row displays the first three entity names alphabetically with "+X others" — hovering reveals the full list.

* **Entity-specific files:** An admin sets up a connector where each entity has a different file structure. Each entity gets its own definition row. The system does not prompt for grouping.

* **New entity added to account:** After an "All Entities" definition is saved, a new entity is added to the customer's account. The admin re-saves the definition with "All Entities" selected, and the definition updates to include the new entity.

* **Overlap detection:** An admin creates two separate definitions the system identifies as sharing the same file structure. The system flags the overlap and offers the option to merge them into a grouped definition.

## 🤔 Assumptions

1. This feature is net new. There are no existing customer connectors that require migration or backfill.

2. A file is considered shared when it has the same column headers, the same accounting period, and is the same file across the selected entities. This is the definition used for overlap detection.

3. Selecting "All Entities" always creates a single grouped definition. The system does not create per-entity rows in this case.

4. When a new entity is added to a customer's account, the admin updates the definition by re-saving with "All Entities" selected. The system reflects the new entity at that point; there is no automatic update.

5. Multi-entity grouping applies to all file types configured in Data Studio, including Chart of Accounts, balance, and dimension files.

6. Entities within a grouped definition are displayed in alphabetical order everywhere they appear in the UI.

7. Grouped definitions and per-entity definitions can coexist on the same connector where file structures differ across entities.

## ⭐ Milestones

1. **Phase 1 — Multi-entity selection and grouped definitions:** Multi-select entity picker in Entity Scope tab; "All Entities" creates a single grouped definition; grouped source row with entity subset display (first 3 alphabetically + hover); single row in source data model view for grouped definitions; edit flow for grouped definitions.

2. **Phase 2 — Overlap detection:** System detects when separately created definitions share the same file structure and prompts the admin to consider merging.

## Scope

**In scope:**

* Multi-select entity picker in the Entity Scope tab, including an "All Entities" option, for all file types

* Single grouped definition created when "All Entities" is selected

* Grouped source row display: first 3 entity names shown alphabetically, "+X others" on hover reveals full list

* Single row in the source data model view when multiple entities are covered by one grouped definition

* Overlap detection for definitions sharing the same file structure, with a merge prompt

* Edit flow for adding or removing entities from a grouped definition, including re-saving to capture newly added entities

**Out of scope:**

* Grouping across connectors

* Automatic merging of definitions without user confirmation

* Automatic update of grouped definitions when new entities are added to an account

* Changes to how entity data is ingested or normalized downstream once a grouped definition is saved

## 🎨 User Interaction and Design

### Entity Scope tab — entity selection

The entity picker supports single-select, multi-select with checkboxes, and an "All Entities" shortcut at the top of the list. Entities are listed in alphabetical order. Selecting multiple entities and saving creates one definition row. Selecting "All Entities" creates one definition row labeled to indicate full coverage. This behavior is consistent across all file types.

### Grouped source row — connector view and model view

A grouped definition displays as a single row in both the connector source view and the source data view for a model. Entities are shown inline in alphabetical order: up to three names appear directly. If more than three entities are covered, "+X others" follows the third name. Hovering over that label opens a tooltip or popover listing all covered entities in alphabetical order.

### Overlap detection prompt (Phase 2)

After a definition is saved, if the system detects a structural match with an existing definition (same headers, same accounting period, same file), a non-blocking banner or modal appears identifying the overlapping definitions and offering to merge. The admin can accept, modify, or dismiss. Dismissed items appear in a review section within the Entity Scope tab.

### Edit flow

Clicking the edit action on any definition row opens the entity picker pre-populated with the current selection. The admin adjusts the entity list and saves. The definition updates in place. Re-saving with "All Entities" selected incorporates any entities added to the account since the last save.

## ⚠️ Out of Scope

* Grouping entity definitions across connectors

* Automatic merging of overlapping definitions without user confirmation

* Automatic update of grouped definitions when new entities are added to an account

* Changes to downstream data ingestion, normalization, or model behavior based on grouped vs. individual definitions

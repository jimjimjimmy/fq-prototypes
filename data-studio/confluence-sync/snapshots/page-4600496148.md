# 1. Objective

This sub-PRD covers the two backend-driven flows that enable an Intacct API connection to be fully configured without any manual setup by the user after initial credential entry.

**Auto-Setup (Setup Link):** Today, when a customer sets up FloQast for the first time, they enter ERP credentials as part of the initial onboarding flow. This already exists. When a customer does this for an Intacct API connection, those credentials should automatically trigger the creation and configuration of their Intacct connection in Data Studio — with no additional steps required from the user.

**Auto-Mapping:** Once a standard Intacct API connection is created — whether via the onboarding flow or manual setup — the standard lineages and field mappings for the Intacct API should be automatically applied. The user should not need to configure anything.

Together, these two flows mean that by the time a user first opens Data Studio, their Intacct connection is already created, credentials are stored, and standard mappings are in place.

# 2. Requirements

**REQ-01: As a FloQast customer, I want my Intacct connection in Data Studio to be automatically created when I enter my Intacct credentials during FQ onboarding so that I do not need to manually set up the connection in Data Studio.**

*Functional spec: When a customer enters Intacct credentials (Company ID, User ID, Password, and optionally Client ID) during the FQ initial setup flow, the system automatically: (1) validates the credentials against the Intacct API by establishing a session token, (2) creates a Data Studio connection record with status ACTIVE, and (3) stores the credentials securely. This happens entirely on the backend. The user is not redirected to Data Studio and is not required to take any additional action. If credential validation fails, the error is surfaced in the onboarding flow with guidance to correct the credentials before proceeding. Client ID is treated as optional; if not provided, the system proceeds without it.*

**REQ-02: As a FloQast customer, I want the Data Studio UI to reflect my Intacct connection as already configured when I first open it so that I can see the connection without having set it up manually.**

*Functional spec: When a user navigates to the Connectors section of Data Studio after auto-setup, the Intacct API connection is visible with status ACTIVE, credentials populated (masked), and the connection Settings page fully accessible. The connection should appear indistinguishable from one set up manually through the Data Studio wizard. No additional configuration steps should be presented to the user as required beyond entity assignment.*

**REQ-03: As a FloQast customer, I want the standard Intacct API field mappings to be automatically created when my connection is set up so that data flows into FloQast correctly without any manual mapping configuration.**

*Functional spec: When a standard Intacct API connection is created — via either the auto-setup flow (REQ-01) or manual connection creation in Data Studio — the system automatically applies the standard Intacct API mapping configuration. This includes creating the predefined lineages for Accounts and GL Balances, applying the default reporting book (ACCRUAL), and leaving adjustment book configuration empty by default. No user action is required to trigger or configure this. The auto-mapping fires as part of the connection creation sequence, after credential validation succeeds and the connection is saved.*

**REQ-04: As a CS team member or Engineering team, I want auto-setup failures to be surfaced clearly so that I can diagnose and resolve them without requiring the customer to repeat the onboarding flow.**

*Functional spec: If any step in the auto-setup sequence fails (credential validation, connection creation, or auto-mapping), the failure is logged with sufficient detail to diagnose the root cause. Failures in auto-mapping should not roll back a successfully created connection — the connection remains ACTIVE and the mapping failure is surfaced separately, allowing it to be retried or corrected without repeating credential entry. Observability requirements are defined in Sub-PRD 6: Notifications & Logging.*

# 3. Auto-Setup Sequence

The following describes the end-to-end sequence triggered when a customer enters Intacct credentials during FQ onboarding.

**Step 1 — Credential Entry (existing flow)**\

Customer enters Intacct credentials (Company ID, User ID, Password, and optionally Client ID) in the FQ initial setup flow. This step already exists today.

**Step 2 — Credential Validation (existing flow)**\

The system makes a live authentication call to Intacct using the provided credentials by establishing a session token. If validation fails, an error is surfaced in the onboarding flow. The customer corrects credentials and resubmits. No connection record is created until validation succeeds.

**Step 3 — Connection Creation (new)**\

On successful validation and save from the user, the system creates a Data Studio connection record:

* Connection name: auto-generated (e.g., `Intacct API`)

* Auth credentials: stored securely (masked in UI)

* Status: `ACTIVE`

* Created via: `SETUP_LINK` trigger

**Step 4 — Auto-Mapping (new)**\

Immediately following connection creation, the system applies the standard Intacct API mapping configuration:

* Standard lineages created for Accounts and GL Balances

* Default reporting book set to `ACCRUAL`

* Adjustment books left empty by default (configurable post-setup)

* Field mappings applied per the Intacct API standard mapping definition

* No user action required

**Step 5 — Ready State**\

When the customer opens Data Studio, the Intacct connection is visible and fully configured. The Connectors view shows the connection as ACTIVE with all standard mappings in place.

---

# 4. Standard Mapping Definition

The auto-mapping step (REQ-03) applies the standard configuration for an Intacct API connection defined in the Mapping Sub-PRD. This is the baseline that all Intacct API connections receive on creation.

> **Note:** The specific field-level mapping definitions (source field → FQ field) are maintained by the Data Platform team and are applied as a versioned standard mapping config. Mapping version is stored on the connection record. Changes to the standard mapping config do not automatically update existing connections — they apply to new connections only unless explicitly migrated.

# 5. User Interaction and Design

## What the user experiences during onboarding

* The customer enters Intacct credentials (Company ID, User ID, Password, and optionally Client ID) in the existing FQ setup flow — no new screens or steps are added.

* If credentials are invalid, an inline error is shown with guidance to correct them. The flow does not progress until credentials are valid.

* No indication that Data Studio setup is occurring is required (it is a background operation), but a success state can confirm that the ERP connection is active.

## What the user sees in Data Studio

* Navigating to **Data Studio > Connectors** shows the Intacct API connection listed with status **ACTIVE**.

* The connection Settings page shows credentials (masked), entity scope (if already assigned), and standard mappings applied.

* No setup prompts or incomplete-state banners are shown.

* The connection is fully functional for sync scheduling and on-demand sync immediately.

# 6. Acceptance Criteria

**REQ-01 — Auto-Setup from Onboarding**

- [ ] Entering valid Intacct credentials (Company ID, User ID, Password, and optionally Client ID) in the FQ onboarding flow automatically creates a Data Studio connection record with status ACTIVE.

- [ ] No additional user action in Data Studio is required after credential entry.

- [ ] If credential validation fails during onboarding, an error is shown in the onboarding flow and no connection record is created.

- [ ] Client ID is treated as optional; absence of a Client ID does not prevent connection creation if other credentials are valid.

**REQ-02 — Connection Visible in Data Studio**

- [ ] After auto-setup, the Intacct API connection is visible in Data Studio > Connectors with status ACTIVE.

- [ ] The connection Settings page shows credentials (masked) and is fully accessible.

- [ ] The auto-created connection is indistinguishable in the UI from one created manually.

**REQ-03 — Auto-Mapping on Connection Creation**

- [ ] Standard Intacct API lineages (Accounts, GL Balances) are automatically created when the connection is established.

- [ ] The default reporting book (ACCRUAL) is applied automatically; adjustment books are left empty by default.

- [ ] No user action is required to trigger or configure the standard mapping.

- [ ] Auto-mapping fires as part of connection creation for both onboarding-triggered and manually created connections.

- [ ] The mapping version applied is stored on the connection record.

**REQ-04 — Failure Handling**

- [ ] Auto-mapping failures do not roll back a successfully created connection.

- [ ] Auto-setup failures are logged with sufficient detail to diagnose without requiring the customer to repeat onboarding.

- [ ] A mapping failure is surfaced separately from the connection and can be retried independently.

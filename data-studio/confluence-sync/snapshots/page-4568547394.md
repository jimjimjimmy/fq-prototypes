## Objective

This sub-PRD defines the end-to-end experience for setting up a CDC connection in Data Studio. It covers source selection, credential entry, table provisioning (standard and optional), connection validation, and the configuration of related companion connector types. A successful setup produces a validated, active connection with the correct tables selected and ready for the initial data load.

---

## Background

CDC connections are powered by Fivetran. The setup experience in Data Studio abstracts the underlying platform - admins interact with sources (e.g., "NetSuite"), not with Fivetran directly. This sub-PRD supersedes the existing Data Studio: CDC Connection Setup (DRAFT), which covered CDC-1 through CDC-12.

The setup wizard follows a four-step pattern consistent with other connector flows in Data Studio:

**Connectors tab → Create Connector → Select Source → Step 1: Name → Step 2: Credentials → Step 3: Provision → Step 4: Validate**

Source-specific credential fields, standard table sets, and companion connector types are defined in the source-specific PRDs for NetSuite, Intacct, and Workday.

## Requirements

### CS-1 — Select a Source

**User story:** As a FloQast Admin, I want to select a data source to connect so that I can get started without choosing a connection type manually.

**Importance:** High

**Details:** From the Connectors tab, the admin initiates a new connection by choosing from a list of FloQast-supported sources. The system routes to the correct setup flow based on the source selected. The admin is never asked to choose "CDC" explicitly - source selection determines the connection type.

**Acceptance criteria:**

* AC-CS-1-01: Given I am on the Connectors tab, I see an option to add a new connection.

* AC-CS-1-02: Given I initiate a new connection, I see a list of FloQast-supported sources.

* AC-CS-1-03: Given I select a source, I am taken into that source's setup flow without being asked to choose a connection type.

---

### CS-2 — Configure Source Credentials

**User story:** As a FloQast Admin, I want to enter my source system credentials so that Data Studio can establish a connection to my data.

**Importance:** High

**Details:** After selecting a source, the admin sees the credential fields specific to that source. Each field includes inline guidance on where to find or generate the required value. A "Test Connection" action validates credentials before the admin can proceed. Credential requirements vary by source and are defined in source-specific PRDs.

**Acceptance criteria:**

* AC-CS-2-01: Given I have selected a source, I see only the credential fields relevant to that source.

* AC-CS-2-02: Each credential field includes inline guidance on where to find or generate the required value.

* AC-CS-2-03: Given I click "Test Connection," the system validates my credentials before allowing me to proceed and that a Fivetran initial sync can successfully kick off.

* AC-CS-2-04: Given credentials are invalid, I see an actionable error message identifying what failed and how to fix it.

* AC-CS-2-05: Credentials are stored securely and not displayed in plain text after entry.

---

### CS-3 — Standard Table Provisioning

**User story:** As a FloQast Admin, I want the system to automatically pre-select the standard tables for my source so that the data required for FloQast standard models is always included.

**Importance:** High

**Details:** After credentials are validated, the admin sees the FloQast-supported table list for their source. Standard tables - those required for FloQast standard models - are pre-selected and locked. Admins cannot deselect them. Tables outside the FQ-supported list are not shown.

**Acceptance criteria:**

* AC-CS-3-01: Given my credentials are valid, I see only the tables in the FloQast-supported list for this source.

* AC-CS-3-02: Standard tables for this source are pre-selected by default.

* AC-CS-3-03: Standard tables are visually distinguished from optional tables.

* AC-CS-3-04: Standard tables cannot be deselected.

* AC-CS-3-05: At least one table must be selected to proceed.

---

### CS-4 — Optional Additional Table Selection

**User story:** As a FloQast Admin, I want to select additional tables beyond the standard set so that I can bring in data needed for custom or extended models.

**Importance:** Medium

**Details:** Admins may add supported tables that are not in the standard set. These are optional and can be added during initial setup or later from connection settings. Adding tables post-setup triggers a data load for only the newly added tables - existing tables are not re-synced.

**Acceptance criteria:**

* AC-CS-4-01: Given I am on the table selection step, I can add optional tables from the FQ-supported list.

* AC-CS-4-02: Optional tables are clearly distinguished from standard tables.

* AC-CS-4-03: I can search or filter the table list to find specific tables.

* AC-CS-4-04: Given I navigate to an existing connection's settings, I can add optional tables post-setup.

* AC-CS-4-05: Adding tables to an existing connection triggers a data load for only the newly added tables; existing tables are unaffected.

* AC-CS-4-06: Each table in the list displays its name, a description of what data it contains, and its current activation status.

---

### CS-5 — Validate and Confirm Connection

**User story:** As a FloQast Admin, I want to confirm that my connection is valid and my selected tables are accessible before setup completes.

**Importance:** High

**Details:** The final step of the setup wizard runs per-table validation using the provided credentials. Each selected table shows a pass/fail status. If all tables pass, the admin can save and begin the initial data load. If any table fails, the admin sees an actionable error and cannot proceed until resolved.

**Acceptance criteria:**

* AC-CS-5-01: The validation step runs automatically when Step 4 is reached.

* AC-CS-5-02: Each selected table displays an individual validation status (success or failure).

* AC-CS-5-03: Given all tables validate successfully, "Save & Connect" is enabled.

* AC-CS-5-04: Given one or more tables fail validation, "Save & Connect" is disabled and I see an actionable error per failed table.

* AC-CS-5-05: Given the connection is saved, it appears on the Connectors tab with "Initial Data Load" status.

---

### CS-6 — Configure a Companion Connector

**User story:** As a FloQast Admin, I want to configure a companion connector alongside my primary CDC connection so that I can bring in supplementary data from the same source that is not available via CDC.

**Importance:** Medium

**Details:** Some sources have companion connector types that provide data not available through the CDC stream. For example, Workday pairs a Workday Financial Management connection with a Workday RaaS (Report-as-a-Service) connector that pulls report-based data. The companion connector is configured during or after primary setup, uses its own configuration fields, and appears as related on the Connectors tab. Which companion types are available for each source is defined in the source-specific PRDs.

**Acceptance criteria:**

* AC-CS-6-01: Given a source supports a companion connector, I am offered the option to configure it during or after primary CDC setup.

* AC-CS-6-02: The companion connector configuration uses its own fields, separate from the primary connection credentials.

* AC-CS-6-03: On the Connectors tab, the companion connector is shown as linked to the primary CDC connection.

* AC-CS-6-04: The companion connector can be added to an existing CDC connection post-setup.

* AC-CS-6-05: The companion connector's status is tracked independently of the primary CDC connection.

## Assumptions

* The setup wizard follows the same 4-step pattern used by other connector types in Data Studio.

* Source-specific credential fields and standard table sets are defined in source-specific PRDs.

* Standard tables cannot be deselected — they are required for FloQast standard models.

* Fivetran is never referenced in user-facing copy.

* Connections cannot be changed to a different type after setup. A new connection is required if the type must change.

* The FQ-supported table list per source must be defined before self-serve table selection can ship.

---

## Dependencies

* FQ-supported table list per source must be defined and maintained (PM + Engineering ownership).

* Source-to-Target mappings must exist for all standard tables before setup auto-creates draft models.

* Source-specific PRDs define credential fields, standard table sets, and companion connector types.

* Sub-PRD 5 (Data Pipeline) covers the initial data load and sync scheduling that begins after setup completes.

* Sub-PRD 2 (Data Mapping & Dimensions) covers how models are auto-created after the initial data load.

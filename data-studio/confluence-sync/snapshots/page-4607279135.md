> **Context:** The Intacct Direct API connection provisions a standard set of endpoints automatically on setup. This sub-PRD defines what those standard endpoints are, how they are auto-provisioned, how admins can add custom endpoints for additional data needs, how GL Balances dimensional parameters are configured, and how the full endpoint lifecycle (activate, deactivate, edit, delete) is managed. All Intacct endpoints communicate over a single HTTPS POST endpoint using XML request/response payloads. This document follows the patterns established in the [Direct API Data Platform 2.0 Data Ingestion PRD](https://floqast.atlassian.net/wiki/spaces/Data/pages/4490330192) and its child pages.

---

## 1. Feature Overview

A Sage Intacct Direct API connection exposes financial data through a defined set of XML API operations. Accounts, GL Balances, and the supporting configuration endpoints (Periods, Currencies, Books, Locations) are all provisioned automatically on connection creation. Customers who need additional data can configure custom endpoints by providing the endpoint path and parameters directly — no support ticket required.

Unlike generic REST API connections, Intacct Direct API endpoints use a fixed XML API structure. Admin-facing configuration for standard endpoints is limited to the parameters those operations natively support.

### 1.1 User Stories

| Story ID | User Story |
| --- | --- |
| US-EP-01 | As a Data Studio admin, I want all standard endpoints provisioned automatically when I set up an Intacct connection so that I don't have to configure them manually. |
| US-EP-02 | As a Data Studio admin, I want to see all active endpoints for my Intacct connection in one view so that I understand what data is being collected and the health of each endpoint. |
| US-EP-03 | As a Data Studio admin, I want to add a custom endpoint by providing the endpoint path and configuration so that I can bring in additional data without filing a support ticket. |
| US-EP-04 | As a Data Studio admin, I want to configure dimensional options on the GL Balances endpoint (reporting book, location, department, vendor) so that balance data is broken down at the right level of granularity for my organization. |
| US-EP-05 | As a Data Studio admin, I want to deactivate an endpoint without deleting it so that I can pause data collection while preserving the configuration and run history. |
| US-EP-06 | As a Data Studio admin, I want to see the status of each endpoint and access logs for every sync operation so that I can monitor health and troubleshoot failures without engineering support. |

## 2. Standard Endpoint Auto-Provisioning

### 2.1 Standard Endpoints

The following endpoints are automatically provisioned when a new Intacct Direct API connection is created. All are required to support the full connection — the core data endpoints (Accounts and GL Balances) depend on the supporting configuration endpoints for period resolution, currency handling, book configuration, and location hierarchy.

**Core data endpoints:**

| Endpoint Name | XML API Function / Object | Data Returned | Default Sync Frequency |
| --- | --- | --- | --- |
| Accounts | `readByQuery` → `glaccount` | Chart of accounts — account number, name, account type, financial statement classification, normal balance, active status, CATEGORY | Daily (24h) |
| GL Balances | `get_trialbalance` | Period-level account balances including ending balance and derived activity (debits + adj debits − credits − adj credits), by reporting book and location | Daily (24h) |

**Supporting configuration endpoints (auto-provisioned as part of standard setup):**

| Endpoint Name | XML API Function / Object | Data Returned | Primary Use Case |
| --- | --- | --- | --- |
| Periods | `readByQuery` → `reportingperiod` | Reporting period definitions — name, start date, end date, period type | Period-aware sync scheduling and date resolution |
| Currencies | `readByQuery` → `trxcurrencies` | Currency definitions — ISO code, full name, symbol | Multi-currency balance reporting |
| Books | `readByQuery` → `gcbook` / `useradjbook` | Reporting and adjustment book definitions — book ID, name | Multi-book balance configuration |
| Locations | `readByQuery` → `location` | Location records — location ID, name, parent ID, currency code | Location hierarchy for balance query nesting (see Sub-PRD 9) |

### 2.2 Auto-Provisioning Behavior

On creation of a new Intacct Direct API connection, the system automatically:

1. Creates and activates all standard endpoints (Accounts, GL Balances, Periods, Currencies, Books, Locations).

2. Applies default parameter configuration to each endpoint (see Section 3 for GL Balances dimensional options).

3. Sets sync frequency to 24 hours for each.

4. Displays all standard endpoints in the Source Data section of the connection detail view with Active status.

5. Triggers creation of lineage records for the Accounts and GL Balances data models as part of the same setup action.

No admin action is required. All endpoints are available and scheduled immediately after connection creation completes.

### 2.3 Acceptance Criteria — Standard Provisioning

| AC-ID | Criterion |
| --- | --- |
| AC-EP-01 | On creation of a new Intacct Direct API connection, all standard endpoints (Accounts, GL Balances, Periods, Currencies, Books, Locations) are automatically created, activated, and visible in the Source Data section with a default sync frequency of 24 hours and Active status. |
| AC-EP-02 | Standard endpoints are pre-populated with system-defined descriptions and do not require admin input to activate. |
| AC-EP-03 | Lineage records for Accounts and GL Balances are created as part of the same connection setup action. Failure to create lineage records surfaces an error to the admin and does not silently succeed. |
| AC-EP-04 | Standard endpoints expose Deactivate but not Delete in the action menu. Permanent deletion of standard endpoints is only permitted as part of deleting the entire connection. |

## 3. GL Balances Endpoint Configuration Options

### 3.1 Dimensional Data Options

The GL Balances endpoint (`get_trialbalance`) supports dimensional parameters that filter and segment balance data. These are configured per connection at endpoint setup or via the Edit action. Full custom field definitions are documented in Sub-PRD 4 — Mapping Configuration.

| Dimension | Custom Field | Default State | Notes |
| --- | --- | --- | --- |
| Reporting Book | Reporting Book | Set to default reporting book on setup | Primary `gcbook` used for balance retrieval; adjustment book IDs derived from this |
| Include Reporting Book | Include Reporting Book | On (true) | Controls whether reporting book data is included in balance queries |
| Location | Location | Off (blank = all locations) | Intacct `LOCATIONID` filter; when set, queries only the specified location |
| Include Child Locations | Include Child Locations | On (true) | When a Location is set, recursively includes all child locations via location hierarchy |
| Department | Department | Off (blank = no filter) | Optional department filter on balance query |
| Vendor | Vendor | Off (blank = no filter) | Optional vendor filter on balance query |
| Show Zero Balances | Show Zero Balances | On (true) | Maps to `showzerobalances`; when true, accounts with zero balances are included |

The following fields are always included in every GL Balances request regardless of dimensional settings: period, account, reporting book.

### 3.2 Acceptance Criteria — GL Balances Configuration

| AC-ID | Criterion |
| --- | --- |
| AC-EP-05 | Dimensional options are configurable per connection via the GL Balances endpoint settings. Default values are applied automatically at provisioning per Sub-PRD 4. |
| AC-EP-06 | When a dimensional filter is set, balance records are scoped accordingly. When left blank, the field is omitted from the request and all records are returned. |
| AC-EP-07 | Enabling or changing a dimensional setting on the GL Balances endpoint triggers a re-sync of balance data for the current and prior fiscal year so that the updated configuration is applied historically. |
| AC-EP-08 | The default fields (period, account, reporting book) are always included in the GL Balances request and cannot be removed or disabled by admins. |

## 4. Custom Endpoint Configuration

### 4.1 Overview

Rather than exposing a predefined library of Intacct endpoints, Data Studio allows admins to add custom endpoints by providing the endpoint path and configuration directly. This follows the same UI pattern as API connection endpoint setup, giving admins flexibility to pull additional Intacct data without engineering involvement.

> **UI/Design note:** The custom endpoint setup experience follows the API connection endpoint configuration UI. Final design is TBD pending ongoing API design discussions.

### 4.2 Adding a Custom Endpoint

Admins can add a custom endpoint from the Source Data section of the connection detail view:

1. Admin selects the option to add a new endpoint.

2. Admin provides the endpoint path and configuration (XML API object, query parameters, field mapping, sync frequency, etc.) using the API endpoint setup UI.

3. If a matching endpoint already exists for this connection, the system detects the duplicate and prompts the admin to link the existing configuration rather than create a new entry.

4. Admin saves. The endpoint is activated and appears in the Source Data list with Active status.

### 4.3 Acceptance Criteria — Custom Endpoints

| AC-ID | Criterion |
| --- | --- |
| AC-EP-09 | Admins can add a custom endpoint to an Intacct connection by providing the endpoint path and configuration via the API endpoint setup UI. |
| AC-EP-10 | When an admin attempts to add an endpoint that is already configured for the connection, the system detects the duplicate and presents an option to link the existing endpoint rather than create a new one. |

## 5. Endpoint Lifecycle Management

All Intacct endpoints — standard and custom — follow the lifecycle pattern established in the platform [Endpoint Library PRD](https://floqast.atlassian.net/wiki/spaces/Data/pages/4447568254). This section documents Intacct-specific constraints on top of that pattern.

### 5.1 Edit

Admins can edit the configuration of any active endpoint via the Edit action. Editable fields:

* Sync frequency (default 24h; options: 1h, 2h, 4h, 8h, 12h, 24h) in Source Data. **Note:** if an endpoint depends on another endpoint (e.g., GL Balances depends on Periods and Locations), it cannot be scheduled more frequently than its parent endpoint.

* Dimensional options (GL Balances endpoint only — see Section 3.1) in Field Mappings

* Endpoint-specific parameters in Source Data

### 5.2 Deactivate (Archive)

Deactivation stops all scheduled and on-demand sync for an endpoint but preserves configuration and run history. The endpoint remains visible in the Source Data list in an Archived state and can be reactivated.

For standard endpoints (Accounts, GL Balances, and supporting endpoints): deactivation is permitted only after the admin acknowledges any active lineage records or downstream application dependencies. The system surfaces the affected model fields before the action proceeds.

On reactivation of any endpoint, the admin is prompted to select a data pull start point: from the beginning, from a specific date, from last sync, or going forward only.

### 5.3 Delete

Standard endpoints cannot be permanently deleted individually. They are only removed as part of deleting the entire Intacct connection.

Custom endpoints can be permanently deleted. A confirmation modal is required before deletion proceeds, with explicit language that the action is irreversible and that all configuration and run history will be removed. If the endpoint feeds an active lineage record, the affected model fields are listed in the modal and the admin must acknowledge before deletion is permitted.

### 5.4 Acceptance Criteria — Lifecycle

| AC-ID | Criterion |
| --- | --- |
| AC-EP-11 | Standard endpoints expose Deactivate but not Delete in the action menu. Standard endpoints are only removed when the entire connection is deleted. |
| AC-EP-12 | Deactivating any endpoint that has active lineage records surfaces the affected model fields in a warning before the action is confirmed. The action is permitted after acknowledgment. |
| AC-EP-13 | Deleting a custom endpoint requires a confirmation modal stating the action is permanent and irreversible. The endpoint, its configuration, and its run history are removed on confirmation. |
| AC-EP-14 | On reactivation, the admin is prompted to choose a data pull start point: from the beginning, from a specific date, from last sync, or going forward only. Going forward only is the default. |

## 6. Endpoint Status and Logs

### 6.1 Status Display

Each endpoint in the Source Data section displays a status badge reflecting the most recent known state:

| Status | Color | Meaning |
| --- | --- | --- |
| Active | Green | Endpoint is enabled and running on schedule |
| Archived | Gray | Endpoint is deactivated; no syncs running; configuration preserved |
| Running | Blue | Sync currently in progress |
| Error | Red | Last sync failed; expand to see error detail |

Auth failures (`XMLGW_JPP0002` — Unauthorized) and sync errors (parser failures, rate limit exhaustion) are tracked and displayed as distinct error categories per endpoint. See Sub-PRD 6 for the full platform log schema.

### 6.2 Log Requirements

Every sync operation — scheduled or on-demand — generates a log entry scoped to the connection and endpoint, following the platform job log schema defined in Sub-PRD 6. Intacct-specific extension: each log entry also records data change counts for that endpoint (records created, updated, and unchanged) to support data freshness auditing.

### 6.3 Acceptance Criteria — Status and Logs

| AC-ID | Criterion |
| --- | --- |
| AC-EP-15 | Every endpoint in the Source Data section displays a status badge reflecting the most recent known state (Active, Archived, Running, Error). |
| AC-EP-16 | Every sync operation on any endpoint — scheduled or on-demand — produces a log entry accessible from the connection detail view. |
| AC-EP-17 | Auth errors and sync errors are displayed as distinct error categories on the endpoint. Errored endpoints show an inline error summary expandable to full error detail. |
| AC-EP-18 | Each log entry includes Intacct-specific data change counts: records created, updated, and unchanged for that endpoint run. |

## 8. Edge Cases & Error Handling

| Scenario | Expected Behavior |
| --- | --- |
| Admin enables a dimensional filter but the Intacct role lacks access to that record type | Sync runs; dimension field returns empty for affected records. Warning logged: "Dimension \[name\] returned no data. Verify that the connected Intacct role has access to \[record type\]." |
| Rate limit error (`XMLGW_JPP0001`) encountered during sync | Retry with backoff per platform retry policy. Progress logged incrementally. If retries are exhausted, endpoint status set to Error and log entry written with retry count and final failure reason. |
| Admin deactivates Accounts endpoint while a GL Balances sync is in progress | The running sync completes. Deactivation takes effect at the start of the next scheduled window. |
| Reactivation of GL Balances endpoint after extended deactivation | Admin is prompted to choose pull start point. If "from the beginning" is selected and the resulting data volume is large, a warning is shown consistent with initial-sync behavior. |
| Admin sets GL Balances sync frequency more frequently than the Locations or Periods endpoint | System prevents the configuration and displays a warning: "GL Balances cannot sync more frequently than its dependent endpoints (Periods, Locations). Update dependent endpoint frequency first." |

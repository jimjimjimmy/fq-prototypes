#### 1. Credential Management

* Ability for customers to configure and store ERP or sFTP credentials within Studio

* Secure credential storage and retrieval

* Connection testing and validation (confirm credentials work before saving)

* Connection status visibility (active, expired, error)

* Credential refresh/rotation support

#### 2. Data Source Configuration

* Connections are shared across applications — a single connection can serve JEM, analytics, and other Studio use cases

* Ability to configure which applications are enabled for a given connection

* Configuration of which dimension types are relevant per customer per application (e.g., which dimensions JEM needs for a given customer)

#### 3. Dimensional Master Data Ingestion

Studio needs to ingest the **full list** of valid dimension values — not just values that appear on existing transactions — from two patterns:

**a. ERP API Pull (direct integrations)**

* Pull complete dimension master data from the ERP on a defined schedule

* Support for all dimension types JEM uses (vendors, departments, cost centers, projects, locations, etc.)

* Incremental refresh to catch additions/retirements in the ERP

* Handling of ERP-specific dimension structures

**b. sFTP File Upload (file-based customers)**

* Accept customer-uploaded CSV files containing dimension data via sFTP

* File format specification and validation

* Processing pipeline from file landing to stored, queryable data

* Error handling and customer notification on bad files

**c. Data Validation**

* Validate that data is populated for the dimension types that have been configured for the customer

* Handling of retired/inactive dimension values (should JEM see them or not?)

* Audit trail of when dimension data was last updated per customer

#### 4. Core Data API (JEM Consumption Layer)

* API endpoint(s) for JEM to query dimension data by customer and dimension type

* Support for returning full value lists (all valid options for a given dimension)

* Filtering support (e.g., active-only vs. all including inactive)

* Freshness indicator so JEM knows how recently the data was synced

---

#### Out of Scope for Now

* **Dependency modeling** — cascading dimension relationships (e.g., valid departments given a subsidiary) will not be in the initial scope

* **Outbound / JE posting** — how JEs get pushed to ERPs is a separate workstream pending Engineering input on a centralized approach

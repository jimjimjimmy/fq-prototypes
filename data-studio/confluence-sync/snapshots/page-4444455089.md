## What Is This?

This is the top-level index for the Model Creation PRD suite. The full requirements are broken into five focused sub-PRDs, each covering a distinct phase of the workflow. Use this page to understand context, shared definitions, and navigate to the right sub-PRD for detailed requirements.

**A Model** is the source-to-target mapping capability within FloQast Data Studio. It enables admins and implementation team members to bring in external datasets, define how fields from those datasets map to the FloQast normalized data format, and publish that configuration so downstream FQ products (Close, Flux, Compliance, Consolidation) can consume the data on behalf of customers.

## Objective

This PRD suite defines the requirements for Model creation — from initiating a new model through publishing it — covering:

* Creation and naming of a new Model
* Establishing Linked Dataset(s) and Grouped Dataset(s)
* Defining Field Mappings (AI-driven, AI-assisted, and manual)
* Testing the mappings against source data
* Publishing the model and managing its version lifecycle
* Viewing processed pipeline output via the Data Preview tab

Primary users: FloQast admins and implementation team members who configure, inspect, and troubleshoot Models without engineering involvement.

## Why This Is Important

Model creation is a critical step in onboarding customers to the FloQast Data Studio platform. Today, setting up Models requires significant engineering involvement — both from the FQ implementation team and from the customer's IT organization. This creates onboarding delays, increases support costs, and limits how quickly customers can go live with FQ data-dependent products.

By making Model creation fully self-service and AI-native, we:

* Reduce time from contract to first data in FQ products
* Eliminate the need for FQ engineering involvement in standard onboarding scenarios
* Simplify IT requirements for customers
* Scale our implementation capacity without adding headcount

**Key example:** One customer delivers 200+ files representing the same dataset split by entity. Without Grouped Dataset support, they would need to manually configure separate model rules per file — an approach that does not scale and introduces high error risk. This work directly addresses that gap.

---

## Key Benefits

* **Zero-engineering model creation:** Admins and implementors can configure, activate, and edit Models from Data Studio without opening a support ticket.
* **AI-native mapping:** AI auto-suggests field mappings on first load, reducing the most time-intensive step of configuration from hours to minutes.
* **Grouped Dataset support:** Eliminates the per-file configuration burden for customers with schema-identical, entity-split data sources.
* **Faster time to first data:** Self-service creation compresses the onboarding timeline.
* **Safer updates via versioning:** Changes to mappings go through a Draft → Publish workflow, preventing untested changes from immediately affecting live data.
* **Pipeline output visibility:** The Data Preview tab gives users direct access to processed pipeline data for validation and audit.

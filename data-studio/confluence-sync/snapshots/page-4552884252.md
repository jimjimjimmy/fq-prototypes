# Data Studio: Onboarding Guide

A quick-start guide for engineers setting up and using FloQast Data Studio.

---

## Where to Find It

1. Log in to FloQast
2. Click the **gear icon** (Settings) in the navigation
3. Go to **Data Studio**

---

## Overview: Three Tabs

| Tab | Purpose |
| --- | --- |
| **Connectors** | Define how data is transmitted into FloQast (start here) |
| **Catalog** | Create models that map source data to FloQast canonical models |
| **Logs** | View activity and run history |

Start with **Connectors** — the catalog and modeling steps depend on having connectors set up first.

---

## Step 1: Create a Connector

A connector defines the transport mechanism for incoming data.

1. Go to the **Connectors** tab
2. Click **Add Connector**
3. Select the connector type (e.g., **SFTP**)
4. Give it a name (e.g., `abc-sftp`) and save

You can have multiple connectors for a given top-level customer (TLC).

---

## Step 2: Configure the Connector

After saving, you can configure the connector's settings.

### Add a User (SFTP)

Under the connector settings, add a user. For SFTP, this is the username + credentials the customer will use to push data to FloQast.

### Add a File (Dataset Definition)

1. Go to the **Files** tab within the connector
2. Click **Add File**
3. Enter a name for the file (e.g., `Quarter to Date Transactions ABC`)
4. **Upload a sample file** — drag and drop a representative file

**This step is critical.** The sample file is used to infer the source schema, and that schema is referenced when building recipes (source-target mappings / lineage).

5. Specify the **file pattern** — the naming convention the system uses to recognize incoming files
6. Select the **load type**

### Configure Accounting Period

1. Re-open the file (click back in → **Edit**)
2. Set up **Accounting Config** — this defines which accounting period the file belongs to. This is often encoded in the file name.
3. Click the **Approve** action

### Set Entity Scope

Entity scope maps the source data to a FloQast entity.

1. Open **Entity Scope**
2. Select the entity from the available entities dropdown
3. Indicate whether the file has a header row
4. Set the data range if applicable
5. Click **Accept**, then **Save**

The connector will now appear on the main Connectors page.

---

## Step 3: Create a Model (Catalog)

A model defines how source data — coming from an external system via a connector — maps to a FloQast canonical data model.

1. Go to the **Catalog** tab
2. Click **Add Model**
3. Enter a model name (e.g., `ABC Accounts`)
4. Select the **model type**
5. Click **Save**

Selecting the model name and type is what causes the system to pull in available data sources. Don't skip this before saving.

---

## Step 4: Add a Data Source to the Model

After saving the model, you'll see a **Data Sources** section. These are the connectors (source datasets) you configured earlier.

1. Hover over a source dataset and click the **+** button to add it to **Primary.**
2. Click **Save**

This unlocks the **Mapping** step.

---

## Step 5: Field Mapping

Mapping is where you define how each source field populates a FloQast model field.

The mapping table shows:

| Column | Description |
| --- | --- |
| **Model Field** | The target FloQast field |
| **Source Field** | The incoming field from your data source |
| **Data Type** | The FloQast data type (only editable for custom fields) |
| **Raw Data** | A preview of the raw source value |
| **Transform** | The transformation function applied (if any) |
| **Transform Data** | A preview of the value after transformation |

FloQast will attempt to auto-map source fields to model fields. Required fields are flagged — these must be mapped before you can publish.

You can also **add custom fields** for data that doesn't map to a standard model field.

---

## Step 6: Apply Transformations

If a source field needs to be normalized or reshaped:

1. Click the **lightning bolt icon** on the field row
2. The transformation pipeline opens, showing the original raw values
3. Browse the **function library** and select a function (e.g., `Split Column`)
4. Configure the function (e.g., set a delimiter like space, choose the index)
5. Click **Run Preview** to verify the output
6. Click **Apply** to confirm

The mapping row will now show the transform function and the resulting transformed data.

7. Click **Save**

---

## Step 7: Publish

Once all required fields are mapped (and any transforms are applied), the **Publish** button becomes available. Publishing activates the model and makes it ready for use in runs.

---

## Quick Reference: Setup Order

```
Connectors tab
  └── Add Connector (SFTP)
        ├── Add User (auth credentials)
        └── Add File (dataset)
              ├── Upload sample file
              ├── Set file pattern + load type
              ├── Configure accounting period
              └── Set entity scope

Catalog tab
  └── Add Model
        ├── Select model name + type → Save
        ├── Add data source (connector)
        ├── Field Mapping
        │     ├── Auto-map where possible
        │     ├── Manually map required fields
        │     └── Apply transforms as needed
        └── Publish
```

# 1. Objective

This sub-PRD defines the requirements for assigning and managing FQ entities on an Intacct direct API connection. Entity assignment is how data pulled from the Intacct API is tagged with the correct FloQast entity, so that downstream products (Close, Reconciliations, JEM, Transform) receive properly scoped data.

For the ERP File Connector, entity scope is configured at the file/endpoint level — each file specifies which FQ entity it serves. For the Intacct API connection, entity scope is configured at the **connection level**. A single connection represents a single Intacct account, and the entities assigned to that connection determine how all data from that connection is tagged in FloQast.

This document covers:

* Assigning FQ entities to a connection

* Viewing and updating entity assignments on an existing connection

For the purposes of this document, entities refers to FQ entities. Intacct has its own concept of locations (organizational units within a customer's Intacct account); location selection and mapping is a separate concern addressed in Sub-PRD 4: Mapping Configuration.

# 2. Background: Current vs. New Pattern

|  | ERP File Connector (current) | Intacct API Connection (new) |
| --- | --- | --- |
| Where entity scope is set | Per file / per endpoint | Per connection |
| Who sets it | User editing each file | User configuring the connection |
| Where it lives in the UI | File Config > Entity Scope tab | Connection Settings > Entity Scope section |

The Intacct API connection moves entity assignment to the connection level because the API pulls data for the whole account, not file-by-file. This is consistent with how entity scoping works today — the same FQ entity pattern is preserved, just elevated to the right level.

# 3. Requirements

**REQ-01: As a CS team member or customer IT team, I want to assign one or more FQ entities to an Intacct connection so that data synced from that connection is tagged with the correct entity in FloQast.**

*Functional spec: After a connection is successfully created, an authorized user can assign FQ entities to it from the connection Settings page. The entity assignment defines which FQ entities are in scope for this connection. All data synced via the connection is tagged with the assigned entity or entities.*

**REQ-02: As a CS team member or customer IT team, I want to view the current entity assignments for a connection so that I can confirm which entities are in scope.**

*Functional spec: The connection Settings page includes an Entity Scope section displaying a table of all assigned entities showing the FQ entity name. This view is read-accessible to all users with access to the connection.*

**REQ-03: As a CS team member or customer IT team, I want to add or remove entity assignments on an existing connection so that the entity scope can be updated as the customer's FloQast configuration changes.**

*Functional spec: An authorized user can add new entities to the connection or remove existing ones from the Entity Scope section on the Settings page. Adding an entity tags subsequent synced data with that entity. Removing an entity removes that entity's scope from the connection; data previously tagged with that entity is preserved but no new data will be tagged for that entity. Removing all entities does not delete the connection.*

**REQ-04: As a CS team member or customer IT team, I want the Intacct connection to appear as a single data source in the Source Data section of model creation and management so that the connection is not fragmented by entity assignment.**

*Functional spec: In the Source Data section of model creation and management, the Intacct direct API connection is represented as a single source entry identified by the connection name. It does not appear as multiple separate sources broken out by FQ entity. The number of assigned FQ entities does not affect how the connection is displayed or selected as a source. The assigned FQ entities are surfaced as metadata on the source entry (e.g., via a tooltip or secondary label) where the UI supports it.*

# 4. User Interaction and Design

## Entity Scope Section — Connection Settings Page

The Entity Scope section on the connection Settings page mirrors the existing pattern used in the ERP File Connector, elevated to the connection level.

**Table layout:**

| Assigned Entities |
| --- |
| \[FQ Entity Name\] |

* A user can assign multiple FQ entities to a single connection (one row per entity).

## Assigning Entities

1. User opens the connection Settings page and navigates to the **Entity Scope** section.

2. User selects one or more FQ entities from the available entity list.

3. Each selected entity is added to the table.

4. User saves the entity assignments.

5. Subsequent syncs tag all data with the assigned entities.

## Updating Entity Assignments

1. User opens the Entity Scope section on the Settings page.

2. To **add an entity**: user selects from the entity list; a new row is added.

3. To **remove an entity**: user removes the row; a confirmation prompt notes that new data will no longer be tagged for that entity (existing data is preserved).

4. A user can select from a dropdown of existing FQ entities.

## Source Data Section — Model Creation and Management

The Intacct connection appears as a single entry in the Source Data section, identified by connection name. Assigned FQ entities are displayed as metadata on the entry (e.g., a tooltip or secondary label) so users can confirm scope without the connection fragmenting into multiple source rows.

# 5. Acceptance Criteria

**REQ-01 — Entity Assignment**

- [ ] A user can assign one or more FQ entities to a connection from the Settings page.

- [ ] Data synced via the connection is tagged with all assigned entities.

**REQ-02 — View Entity Scope**

- [ ] The connection Settings page displays an Entity Scope section with a table of assigned entities.

- [ ] The table is visible to all users with access to the connection.

**REQ-03 — Add / Remove Entities**

- [ ] A user can add a new entity to an existing connection.

- [ ] A user can remove an entity from an existing connection; a confirmation prompt warns that new data will no longer be tagged for that entity.

- [ ] Removing an entity does not delete previously synced data tagged with that entity.

- [ ] A user can see a list of existing FQ entities to select from when assigning an entity.

**REQ-04 — Source Data Representation**

- [ ] The Intacct connection appears as a single entry in the Source Data section of model creation and management.

- [ ] The connection is not split into multiple source entries based on the number of assigned FQ entities.

- [ ] Assigned FQ entities are surfaced as metadata on the source entry where the UI supports it.

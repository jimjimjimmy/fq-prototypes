# **1. Objective**

This sub-PRD defines the requirements for an AI-powered setup assistant embedded as the first step of the API connection setup wizard in FloQast Data Studio. The assistant applies to both Pull API connections (Phase 1) and Push API connections (Phase 6).

Rather than requiring admins and implementors to manually research and transcribe API documentation into setup fields, the assistant allows users to paste API documentation, provide documentation URLs, or describe the API in freeform language. From that input, the AI pre-populates the relevant wizard fields for either a pull or push connection. The assistant also supports a bidirectional conversational interface: users can ask questions about how API setup works in FloQast, and the AI can ask clarifying questions when it cannot confidently determine a required value. Fields the AI populates but is uncertain about are flagged for the user to confirm.

The step is optional. Users can skip it at any point and configure all fields manually. The primary users are FloQast admins and implementation team members who frequently set up API connections and benefit from reduced manual lookup and entry - especially for less-familiar APIs or less technical users who need guidance through the process.

# **2. Key Benefits**

* Reduced manual entry: admins no longer need to manually cross-reference API documentation while filling in wizard fields - the AI reads the docs and translates them into configuration.
* Faster setup for less familiar APIs: implementors onboarding customers on APIs they haven't configured before get a head start without needing to deeply study the documentation first.
* Guided experience for non-technical users: the conversational Q&A interface means less technical admins can ask plain-language questions about setup steps and get contextual answers.
* Fewer configuration errors: by pre-populating fields from authoritative documentation rather than manual transcription, the assistant reduces the risk of typos, wrong auth methods, or missed parameters.
* Transparent AI confidence: best-guess fields are flagged for review rather than silently accepted, keeping the human in control of the final configuration.
* Applies to both API directions: the same assistant handles pull and push connection setup, ensuring consistent behavior regardless of integration type.
* Fully skippable: no workflow is blocked by the AI step - users who prefer manual setup or already know the configuration can skip immediately with no friction.

# **3. Use Cases**

1. Documentation-driven pull setup: An implementor is configuring a pull API connection for a customer ERP they haven't worked with before. They paste the API's developer documentation into the AI assistant. The assistant identifies the base URL, auth method, endpoint paths, pagination type, and rate limits, and pre-populates those fields in the wizard. The implementor reviews the pre-filled fields, confirms the flagged best-guess entries, and proceeds to test the connection - skipping the manual research that would otherwise have taken 30+ minutes.
2. URL-based documentation ingestion: An implementor provides two URLs - the API authentication docs and the endpoints reference page. The assistant fetches and parses both, combining the information to pre-populate connection basics, auth type, endpoint configuration, and header requirements. The implementor only needs to fill in the credential values themselves (which the AI deliberately leaves blank for security reasons).
3. Freeform description for push setup: An admin is setting up a push connection from a source system that sends webhook events when journal entries are posted. They describe the integration in their own words: 'Our ERP sends a POST to a webhook URL when a journal entry is created. It includes a signature header for verification.' The assistant identifies the push pattern, suggests HMAC signature verification as the auth method, and pre-fills the event type field. Flagged fields include the specific HMAC header name, which the admin fills in manually.
4. Clarifying question exchange: An admin pastes partial API documentation that describes the endpoints but doesn't specify the pagination method. The assistant pre-fills what it can and then asks: 'I wasn't able to determine the pagination method from the documentation provided. Does this API use cursor-based, offset/limit, or page number pagination?' The admin answers, and the assistant fills in the pagination configuration accordingly.
5. User asking setup questions: An implementor is unsure what 'delta logic' means in the context of the wizard. They type a question into the AI assistant: 'What is delta logic and how do I know which option to choose?' The assistant explains the concept in plain language and, if it can infer the right approach from the documentation already provided, suggests which option to select.
6. Skipping and returning: An admin opens the AI step, decides they already know the configuration details and doesn't need assistance, and clicks Skip. They complete setup manually. Later, when setting up a different connection, they use the AI step to paste documentation and reduce setup time for a less familiar API.
7. Reviewing and editing pre-filled fields: After the AI pre-populates the wizard, an admin reviews the filled fields. Most are correct, but the AI flagged the rate limit value as uncertain. The admin checks the vendor's docs, confirms the value, updates the field, and proceeds. All other pre-filled fields are accepted as-is.

# **5. Assumptions**

* The AI assistant is powered by an internal LLM or an Anthropic API integration. The specific model and infrastructure are to be determined by Engineering and are not defined in this PRD.
* The AI step is optional at all times. Skipping it has no effect on the user's ability to complete setup manually, and no wizard fields require AI assistance to unlock.
* The AI does not pre-populate credential values (e.g., API keys, client secrets, passwords) for security reasons. Credential fields in the authentication step are always left blank for the user to fill in directly.
* URL fetching is performed server-side by FloQast, not by the user's browser, and is subject to the same web content access restrictions as other FloQast backend processes.
* The AI assistant uses the documentation and freeform input provided within the session. It does not have access to prior session history unless the connection was saved as a draft and the user resumes that draft.
* The assistant maps to the field structure of both the Pull API and Push API setup wizards as defined in their respective sub-PRDs. Any field not present in a given wizard type is not pre-populated for that type.
* Fields the AI cannot determine from the provided documentation are left blank (not guessed), unless the AI has moderate-to-high confidence in an inference - in which case the field is pre-populated and flagged for review.
* The AI step is presented before authentication configuration. The assistant may suggest an auth type based on documentation but cannot pre-populate auth credential values.
* The conversational Q&A interface is a text-based chat panel embedded within the AI step - it is not a separate screen or modal.
* Context from the AI step conversation (documentation ingested, clarifying answers given) is passed forward to inform pre-population as the user moves through subsequent wizard steps.

# **6. Milestones**

1. Phase A.1 - Core Pull AI Setup: AI step added as the first step of the Pull API setup wizard. Users can paste documentation text or write a freeform description. AI pre-populates pull wizard fields. Flagged fields displayed with visual indicator and best-guess value. Skip option available. Review screen before advancing shows all AI-suggested values. Applies to Pull API wizard only.
2. Phase A.2 - Bidirectional Q&A and URL Ingestion: Conversational chat panel added to the AI step. User can ask plain-language questions about setup; AI responds contextually. AI can ask clarifying questions when fields cannot be determined from documentation. URL input added: user can provide one or more documentation URLs that the system fetches and parses server-side.
3. Phase A.3 - Push API Support: AI step integrated into the Push API setup wizard (Phase 6 of parent PRD). AI maps ingested documentation to push-specific fields: inbound auth method suggestion, event type definitions, failure handling recommendations, and volume expectations. All Phase A.2 capabilities apply to push flows.
4. Phase A.4 - Refinement and Confidence Calibration: AI confidence scoring refined based on adoption and acceptance rate data. Flagging thresholds adjusted. Improvements to field mapping accuracy based on real-world documentation inputs. Potential addition of structured documentation templates for common API patterns.

# **7. Scope of Data**

The following data objects and entities are in scope for this sub-PRD:

* AI session input: the raw text provided by the user (pasted documentation, freeform description) and any URLs submitted. Stored per wizard session and associated with the draft connection.
* AI-generated field suggestions: the pre-populated field values generated by the AI for each wizard step, including the confidence level per field (confident vs. flagged).
* Flagged fields: a list of fields pre-populated by the AI with a best-guess value that the user must confirm or change before the connection can be activated. Includes the AI's suggested value and a brief rationale.
* Q&A conversation log: the turn-by-turn conversational exchange between the user and the AI assistant within the session, stored as part of the draft connection context.
* URL fetch results: the parsed content from any documentation URLs provided by the user, retained for the duration of the setup session.

‌

Explicitly out of scope:

* Authentication credential values - the AI does not generate, suggest, or store API keys, secrets, tokens, or passwords.
* Field mapping and lineage configuration - covered in a separate PRD.
* Persistent AI memory across separate sessions or connections - the AI context is scoped to the current wizard session or draft connection.
* AI-generated endpoint paths or query parameter values that are not derivable from the provided documentation - the AI does not fabricate configuration values.

# **8. Requirements**

**REQ-01**

**As an admin or implementor, I want the AI setup assistant to appear as the first step in both the Pull and Push API setup wizards so that I have the option to use it before manually filling in any fields.**

_Functional spec:_ The AI assistant step must be presented as the first step in the setup wizard for both Pull (Phase 1) and Push (Phase 6) API connection flows. It must appear before connection basics, authentication, and all other configuration steps. The step must include a clear description of what it does, a text input area for documentation or freeform description, a URL input field, and a Skip option. The Skip option must be visible and immediately actionable - no content is required before skipping.

**REQ-02**

**As an admin or implementor, I want to paste API documentation or write a freeform description of the API so that the AI can understand the integration and pre-fill the setup wizard.**

_Functional spec:_ The AI step must include a text input area that accepts free-form text input of any length, including pasted API documentation, developer portal content, or the user's own plain-language description of the integration. The user may enter any combination of these. The system must accept input and pass it to the AI model for analysis without requiring a specific format.

**REQ-03**

**As an admin or implementor, I want to provide API documentation URLs so that the AI can fetch and analyze the documentation without me having to paste it manually.**

_Functional spec:_ The AI step must include a URL input field that accepts one or more documentation URLs. On submission, the system must fetch the content of each URL server-side and pass the parsed content to the AI model alongside any pasted text. If a URL cannot be fetched (e.g., blocked, requires login, or times out), the system must display a clear inline error and allow the user to continue with the remaining inputs. The URL fetch must not expose the user's browser or credentials to the target site.

**REQ-04**

**As an admin or implementor, I want the AI to analyze my input and pre-populate the relevant wizard fields so that I don't have to manually look up and transcribe every configuration value.**

_Functional spec:_ After the user submits their input, the AI must analyze the documentation and freeform text and pre-populate the relevant fields in the subsequent wizard steps. For Pull API connections, fields in scope for pre-population include: base URL, environment, API version, auth type suggestion, endpoint path, HTTP method, request and response format, headers, query parameters, pagination method, delta logic type, rate limits, and sync frequency. For Push API connections, fields in scope include: source system, inbound auth method suggestion, event types, failure handling recommendation, and volume expectations. Authentication credential values must not be pre-populated under any circumstances.

**REQ-05**

**As an admin or implementor, I want fields the AI is uncertain about to be pre-filled with a best guess and clearly flagged so that I know which values need my attention before proceeding.**

_Functional spec:_ For fields where the AI has inferred a value but is not fully confident, the system must: (1) pre-populate the field with the AI's best guess, (2) display a visual flag or indicator on the field (e.g., a yellow highlight or caution icon) indicating that this value requires user confirmation, and (3) display a brief tooltip or inline note explaining why the field was flagged and what the AI inferred. Fields the AI cannot determine at all must be left blank. The user must be able to confirm, edit, or clear any flagged field. No flagged fields prevent the user from advancing unless they are required fields that have been left blank.

**REQ-06**

**As an admin or implementor, I want to ask plain-language questions about API setup and have the AI respond in context so that I can get guidance without leaving the wizard.**

_Functional spec:_ The AI step must include a conversational chat panel where the user can type and submit natural language questions. The AI must respond with plain-language answers relevant to the Data Studio setup flow. Responses must be contextual - informed by the documentation the user has already provided in the current session. Question and answer exchanges must be displayed in chronological order within the panel. The chat panel must remain accessible throughout the AI step.

**REQ-07**

**As the AI assistant, I want to ask the user clarifying questions when I cannot determine a required field from the provided documentation so that I can produce a more complete and accurate pre-population.**

_Functional spec:_ When the AI identifies a required or high-priority field that it cannot determine from the input provided, it must proactively ask the user a clarifying question via the chat panel. Clarifying questions must be specific (e.g., 'Does this API use cursor-based, offset/limit, or page-number pagination?'), not open-ended. The user's response must be incorporated into the AI's field pre-population. The AI must not ask more than three clarifying questions per session without user-initiated continuation, to avoid making the step feel burdensome. Users can ignore clarifying questions and proceed manually.

**REQ-08**

**As an admin or implementor, I want to skip the AI setup step at any time so that I can configure the connection manually without being slowed down.**

_Functional spec:_ A Skip button must be visible and accessible at all times within the AI step. Clicking Skip must advance the user to the first manual configuration step (connection basics) with all wizard fields blank - no partial AI pre-population must be applied if the user skips before submitting input. If the user has already submitted input and received pre-populated fields, a confirmation prompt must ask whether they want to discard the AI suggestions or keep them. This distinction ensures skip is truly a fresh manual start when desired.

**REQ-09**

**As an admin or implementor, I want to review all AI-suggested field values in a summary view before advancing in the wizard so that I can confirm, edit, or clear any value the AI has pre-filled.**

_Functional spec:_ After the AI completes its analysis and pre-population, the system must present a review panel showing all fields the AI has suggested values for, grouped by wizard step. Each field must display the AI's suggested value and, for flagged fields, the confidence note. The user must be able to edit any value inline from this review panel or clear a value to leave it blank. The user must explicitly confirm the review before the wizard advances to connection basics. Pre-populated values carry forward into the subsequent wizard steps as editable defaults.

**REQ-10**

**As an admin or implementor, I want the AI context from this step to persist throughout the wizard session so that I can return to the AI step or reference my earlier documentation input if needed.**

_Functional spec:_ The AI session context - including the submitted documentation text, parsed URL content, Q&A exchange, and pre-populated values - must persist for the duration of the setup session. If the user saves the connection as a draft and resumes later, the AI context must be restored alongside the saved field values so the user can continue from where they left off. Context must not persist across separate, unrelated connection setup sessions.

**REQ-11**

**As an admin or implementor, I want to upload API documentation so that the AI can understand the integration and pre-fill the setup wizard.**

_Functional spec:_ The AI step must include an option to upload PDF or Word files of any length that include a description of the API configuration. The user may enter this with any combination of other inputs (URL or text). The system must accept input and pass it to the AI model for analysis without requiring a specific format.

# **9. User Interaction and Design**

**Placement in the Setup Wizard**

The AI assistant step is Step 0 - the first screen the user sees after initiating a new API connection setup and selecting their API type (Pull or Push). It precedes all configuration steps. The step is labeled clearly (e.g., 'Set Up with AI Assistance') and includes a one-sentence description of its purpose.

‌

**AI Step Layout**

* Left panel or primary area: Documentation input section with two inputs - (1) a large text area labeled 'Paste API documentation or describe the API' and (2) a URL input field labeled 'Or provide documentation URLs' with an Add URL button to add multiple URLs.
* A Submit / Analyze button initiates AI processing. While processing, a loading state is shown with a brief message (e.g., 'Reading your documentation...'). Processing must complete within a reasonable timeframe; if it exceeds 15 seconds, a progress indicator with an estimated wait must be shown.
* Right panel or collapsible section: Conversational chat panel for the Q&A interface. Displays AI clarifying questions proactively and accepts user-typed questions. Chat history scrollable within the panel.
* Skip button: prominently placed, accessible before and after submitting input. Label: 'Skip and set up manually.'

‌

**Post-Analysis Review Panel**

* After analysis completes, the review panel replaces the input area (or expands below it) and lists all AI-suggested values grouped by wizard section: Connection Basics, Endpoint Configuration, Auth (type suggestion only), Pagination, Delta Logic, Rate Limits, and so on.
* Confident fields shown in standard styling with the suggested value pre-filled.
* Flagged fields shown with a yellow highlight and a caution icon. Hovering or tapping the icon reveals the AI's confidence note (e.g., 'Inferred from context - please confirm this matches your API provider's documentation').
* Blank fields (AI could not determine) shown with an empty input and a note: 'Not found in documentation - you'll fill this in on the next step.'
* An 'Edit' link on each field row allows inline editing from the review panel before advancing.
* A 'Confirm and continue' button advances the user to the connection basics step with pre-filled values applied.

‌

**Behavior in Subsequent Wizard Steps**

* Fields pre-populated by the AI are displayed as editable defaults - visually identical to manually entered values, except flagged fields retain their indicator until confirmed by the user.
* The AI step is accessible from a 'Back to AI setup' link at the top of each wizard step in case the user wants to provide additional documentation or ask follow-up questions.
* If a user edits a pre-populated field, the edit overrides the AI suggestion and the field is no longer flagged.

‌

**Guidance Text (shown in the AI step)**

'Our AI assistant can read your API documentation and pre-fill your connection setup. Paste documentation text, share a URL, or describe the API in your own words - then review what it finds before continuing. You can also ask it questions about any part of the setup process. Skip this step if you prefer to configure everything manually.'

# **11. Out of Scope**

* Authentication credential pre-population - the AI does not generate, suggest, or pre-fill any credential values (API keys, secrets, tokens, OAuth credentials). Credential fields are always completed manually by the user.
* Field mapping and lineage configuration - the AI step supports connection setup only. Mapping from API response fields to the FQ data model is covered in a separate PRD.
* Persistent AI memory across separate connections or sessions - AI context is scoped to the active setup session or draft connection. No cross-connection learning or memory.
* AI-generated endpoint paths or configuration values not derivable from the provided documentation - the AI will not fabricate values. Undetermined fields are left blank or flagged.
* Auto-activation of the connection based on AI output - the user must always review, confirm, and explicitly activate the connection. The AI step does not bypass any validation or review stages.
* Standard pre-built connector setup - the AI-assisted step applies to custom API connections only. Standard connectors (e.g., QBO direct connector) follow their existing setup flows without this step.
* AI suggestions for data transformation or pipeline logic - the assistant is scoped to connection configuration fields only.
* Version history or diff views for AI suggestions across multiple documentation submissions in the same session - out of scope for Phase A.1 and A.2.

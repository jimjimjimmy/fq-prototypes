## Objective

This sub-PRD defines the requirements for API endpoint management within FloQast Data Studio for QuickBooks Online (QBO) connections. Specifically, it covers how Data Studio provisions, displays, and manages QBO REST API v3 endpoints as configurable data sources including a standard set of endpoints auto-provisioned on connection setup.  
  
The primary users are FloQast admins and implementation team members who need to configure, inspect, and troubleshoot QBO data endpoints without engineering involvement.

This work is dependent on https://floqast.atlassian.net/wiki/spaces/Data/pages/4490330192/Direct+API+Data+Platform+2.0+Data+Ingestion+DRAFT 

## Key Benefits

* Zero-engineering endpoint activation: admins and implementors can configure, activate, and edit QBO endpoints directly from Data Studio.
* Faster time to first data: standard QBO endpoints (TrialBalance and Accounts) are auto-provisioned when a new QBO API connection is created, reducing setup friction.

## Use Cases

* Standard QBO setup: A FloQast implementor sets up a new QBO API connection. Data Studio automatically provisions the TrialBalance and Accounts endpoints and displays them in the Source Data section of the connection detail view. No additional configuration is required for standard close workflows.
* Endpoint library browsing: An admin navigates to the QBO connection in Data Studio and opens the endpoint library. They browse available QBO REST API v3 endpoints, see descriptions and current activation status, and activate an additional endpoint (e.g., a custom field endpoint) without opening a support ticket.
* Custom endpoint with query parameters: An implementor adds a non-standard QBO endpoint that requires specific query parameters (e.g., a realmId-scoped report with a date range). They configure the required parameters, and where parameter values depend on data from another endpoint, the system resolves those through a nested endpoint call.

## Assumptions

1. QBO REST API v3 is the stable, supported API surface. FloQast will monitor Intuit developer communications for any deprecation notices.
2. The two standard endpoints for QBO are: (1) reports/TrialBalance with date range and accounting method parameters, and (2) query with a SELECT statement for Accounts. These are the current production endpoints used by FloQast today.
3. Default sync frequency is 24 hours. Admins may adjust this per connection.
4. Rate limit constraints from the parent PRD apply: ~500 requests/minute per realmId. Endpoint configuration and scheduling must operate within this limit.
5. Custom endpoint configurations are scoped per connection (realmId), consistent with the parent PRD's CAS multi-entity requirements.

## Scope

The following data objects and entities are in scope:

* QBO API endpoint configurations: stored per connection (realmId), including: endpoint name, API path, description, query parameters, sync frequency, activation status, and last run metadata.
* Accounts: data retrieved via the QBO query endpoint (SELECT on Account objects). Parsed and classified by account type (balance sheet vs. income statement).
* Trial Balances: data retrieved via the QBO reports/TrialBalance endpoint with date range and accounting method parameters. Balance computed as debit minus credit.
* Query parameter definitions: parameter names, types, whether they are user-defined or resolved from upstream endpoint responses, and the source endpoint if nested.
* Data run logs: per-run metadata including trigger source (scheduled vs. on-demand), start/end time, status, records processed, and error details. This should be partitioned by the TLC and entity/data domain as is relevant.
* Downstream notification events: event payload confirming new data availability, scoped to connection and data object type.

Explicitly out of scope for the data layer:

* GL Transactions, FX Rates, and Companies (covered in parent PRD milestones).
* Field mapping configuration (covered in QBO mapping sub-PRD).
* Fivetran-ingested data objects (covered in QBO Fivetran data tables sub-PRD)

### Connection Detail View: Source Data Section

The Source Data section of the QBO connection detail view must display all configured endpoints for that connection. The list view includes:

* Endpoint name and QBO API path
* Short description of the endpoint's purpose
* Data objects currently populated by this endpoint
* Activation status (Active / Inactive / Error)
* Last successful run timestamp and next scheduled run
* Action links: Edit, Run Now, Deactivate

Standard endpoints (TrialBalance, Accounts) are displayed here automatically after connection setup with no additional action required.

‌

### **Endpoint Library**

Accessible from the connection detail view, the endpoint library is a browsable catalog of available QBO REST API v3 endpoints. The library:

* Lists all available QBO endpoints with name, description, API path, data objects, and current activation status for this connection
* Supports search/filter by endpoint name or data object
* Allows an admin to select and activate an endpoint, which opens the endpoint configuration flow

## Out of Scope

* Write-back or bi-directional sync: This sub-PRD covers read-only data ingestion. No data will be pushed back to QBO.
* GL Transactions, FX Rates, and Companies endpoints: Covered in other QBO sub-PRDs; not part of the initial standard endpoint set defined here.
* Fivetran endpoint management: Fivetran-connected data sources have a separate configuration path and are not governed by this sub-PRD.
* Data preview / test & sample capability: Covered in other PRD. Out of scope here but should be considered in the Phase 2 endpoint configuration flow
* QBO Desktop: This sub-PRD targets QBO Online only.
* Non-QBO integrations: Workday, SAP, Yardi, and other ERP integrations are governed by separate PRDs.

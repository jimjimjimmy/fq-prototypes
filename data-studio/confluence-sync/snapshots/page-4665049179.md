# 1. Objective

This sub-PRD defines the Data Studio product requirements for the SAP ECC prebuilt connector. It covers the end-to-end setup experience a FloQast implementor or CS team completes to connect a customer's SAP ECC environment to FloQast via SFTP, including connector selection, SFTP provisioning, entity mapping, and auto-configuration of data models and mappings. It does not cover the SAP-side ABAP transport installation, job scheduling, or Basis configuration, which are defined in the SAP Integrations Master PRD and its sub-PRDs.

The primary users of this flow are FloQast implementors and CS teams setting up new SAP ECC customers in Data Studio. In some cases, a customer's IT or Basis team may complete steps in collaboration with the FloQast team.

Today, there is no prebuilt SAP ECC connector path in Data Studio. Customers on SAP ECC require manual Engineering involvement for setup, which creates operational overhead and slows time-to-value. This connector formalizes a standardized, repeatable setup path that eliminates per-customer manual configuration. File naming conventions and expected file types are pre-established by FloQast in collaboration with ActionFI and are known at connector setup time — no customer-specific input is required beyond completing the SFTP provisioning and entity mapping steps.

A successful SAP ECC setup through Data Studio means that once a customer's ABAP connector is installed and scheduled, files arrive at FloQast's SFTP server, are automatically recognized as SAP ECC data, and flow through to downstream FloQast products without additional configuration work.

# 2. Key Benefits

* **Standardized connector entry point:** SAP ECC appears as a named, icon-labeled prebuilt connector in Data Studio, making it discoverable and clearly distinct from SAP S/4HANA Private Cloud and generic SFTP connections.

* **Zero file configuration required:** Because naming conventions are pre-established with ActionFI, implementors do not need to configure individual files or provide sample file names — setup is driven entirely by connector type selection.

* **Auto-configured models and mappings:** Standard data models for accounts, balances, GL transactions, FX rates, subledger transactions, companies, and dimensions are created automatically at connection setup.

* **Auto-configured dimensions:** Dimension files and dimension definitions are set up automatically based on the known SAP ECC extract structure.

* **Reduced Engineering involvement:** New SAP ECC customers can be onboarded by CS and implementation teams without manual Engineering intervention.

* **Visibility into configuration:** After setup, implementors can view all auto-created models and mappings directly in Data Studio to validate and review.

* **Extensible for custom fields:** Additional fields in a customer's extract can be added and configured through the standard file workflow edit experience.

* **Platform-native integration:** Once connected, SAP ECC data flows through Data Platform 2.0 and is available to all downstream FloQast products.

# 3. Use Cases

1. A FloQast implementor navigates to Data Studio, selects SAP ECC from the prebuilt connector list, completes the SFTP provisioning steps and entity mapping within the wizard, and finishes setup — at which point Data Studio auto-configures the expected data models, mappings, and dimensions without any additional steps.

2. After completing connection setup, a FloQast implementor navigates to the connection in Data Studio and reviews the auto-created models and mappings to confirm they are correct for the customer before the first file is processed.

3. A customer's Basis team has configured SAP to deliver files to the FloQast SFTP endpoint on a nightly schedule. Data Studio recognizes the incoming files as SAP ECC extracts based on the pre-established naming convention and routes them correctly without manual intervention.

4. A FloQast CS team member checks the connection status in Data Studio and confirms that files have been received and processed successfully after the customer's first scheduled SAP job run.

5. A customer's SAP ECC environment includes custom fields in their extract beyond the standard FloQast set. A FloQast implementor uses the standard file workflow edit experience to add and configure those custom fields.

6. FloQast (system) receives a file on the SFTP server and determines, based on the pre-established naming convention for this connection, that it belongs to this SAP ECC connection rather than a generic SFTP upload, and routes it through the correct pipeline.

# 5. Assumptions

 1. Customers are on SAP ECC and have the FloQast ABAP transport installed and configured by their Basis team prior to completing Data Studio setup.

 2. File delivery to FloQast is via SFTP. The SAP-side SFTP configuration (destination, credentials) is handled by the customer's Basis team outside of this flow.

 3. A standard set of file types is expected from every SAP ECC connection (accounts, balances, GL transactions, FX rates, subledger transactions, companies, dimensions). The exact list is \[TBD pending ActionFI tech spec\].

 4. File naming conventions for SAP ECC extracts are pre-established by FloQast in collaboration with ActionFI. They follow a predictable, standardized pattern that can be used to distinguish SAP ECC files from other SFTP uploads. Customer input is not required to define or confirm these conventions during setup.

 5. Auto-detection of SAP ECC files vs. other SFTP files is technically feasible and will be defined in collaboration with ActionFI.

 6. Auto-configuration logic for standard models, mappings, and dimensions is deterministic and does not require customer-specific input beyond SFTP provisioning and entity mapping.

 7. Volume handling behavior (append, period replace, or full history) for each file type is defined and consistent across all SAP ECC customers. \[TBD — to be confirmed with ActionFI.\]

 8. The standard file workflow edit experience is sufficient to support custom field configuration without changes to the core setup flow.

 9. Data Platform 2.0 is available and able to ingest and normalize SAP ECC extract files.

10. The frequency at which SAP delivers files is configured entirely within SAP and is not managed or set in Data Studio.

# 7. Scope

**In scope:**

* SAP ECC prebuilt connector icon and entry point in the Data Studio connector selection UI

* Standard SFTP connection setup flow scoped to SAP ECC

* Auto-configuration of expected file types at connection setup (no user file naming input required)

* Auto-configuration of standard data models: accounts, balances, GL transactions, FX rates, subledger transactions, companies \[exact list TBD\]

* Auto-creation of standard field mappings for all auto-configured models

* Auto-creation of dimension file definitions and dimension configurations

* Entity mapping as an inline step within the connection setup wizard

* File recognition and routing based on pre-established naming conventions

* Post-setup visibility of auto-created models and mappings in Data Studio

* Standard logging and notifications

* Custom field configuration via standard file workflow edit

**Explicitly out of scope:**

* SAP-side ABAP transport installation, packaging, and Basis configuration (covered in SAP Integrations Master PRD Sub-PRDs 1–2)

* SAP job scheduling configuration (customer-managed in SAP; covered in Master PRD Sub-PRD 3)

* SAP S/4HANA Private Cloud connector (separate sub-PRD)

* SAP S/4HANA Public Cloud (separate initiative, Q4)

* Write-back or journal entry posting to SAP

* Real-time or event-driven data delivery from SAP

* Non-standard SFTP delivery mechanisms

# 9. User Interaction and Design

## Connector Selection

The Data Studio "Add Connection" or prebuilt connector section displays a tile for SAP ECC alongside other prebuilt connectors (NetSuite, SAP S/4HANA Private Cloud, etc.). The tile shows the SAP ECC icon and name. Clicking it begins the SAP ECC connection setup wizard.

## SFTP Setup Step

The user is walked through the standard SFTP provisioning flow. The system provisions SFTP credentials and displays the endpoint details (host, port, username, password or key) for the user to copy and share with the customer's Basis team. This step is functionally identical to the standard SFTP setup flow. No file naming input is requested at any point in the wizard.

## Entity Mapping Step (Within Wizard)

Immediately following SFTP setup, the wizard presents the entity mapping step. The implementor assigns the customer's FloQast entities to the connection. This step is required to complete the wizard. The connection is not activated until entity mapping is confirmed.

## Auto-Configuration on Completion

When the implementor confirms the connection, the system automatically applies the pre-established SAP ECC naming conventions, creates the expected file type configurations, and generates all standard data models (accounts, balances, GL transactions, FX rates, companies, subledger transactions), field mappings, and dimension definitions in the background. The user sees a confirmation state indicating setup is complete and the connection is active and ready to receive files.

## Post-Setup Model and Mapping Review

After setup, the implementor can navigate to the connection in Data Studio and view all auto-created models and their field mappings. This uses the standard model/mapping UI. The implementor can use this view to validate the configuration or identify any custom fields that need to be added via the file workflow edit experience.

## Connection Management / Editing

Once active, the connection can be viewed and edited. Custom fields can be added to any auto-configured model through the standard file workflow edit experience. Standard SFTP connection management (disable, delete, credential rotation) applies.

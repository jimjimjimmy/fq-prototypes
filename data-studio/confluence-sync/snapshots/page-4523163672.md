## 🎯 Objective

This PRD defines **Accounting Config** as it applies to dataset setup in Data Studio. Accounting Config is an existing concept in production — it defines how the platform identifies the accounting period for each file that arrives in a dataset. A file's period can be sourced either from tokens in the filename or from a column inside the file.

In the Add Dataset wizard, Accounting Config is Step 4. In dataset Edit mode, it is accessible directly as a tab.

This PRD does **not** cover entity identification — that is a separate concept handled in Step 5 (Entity Configuration) and should not be conflated with Accounting Config.

Primary users: Data Studio admins and FloQast implementation team members configuring a new dataset within a Connector.

## 🏅 Why This Is Important

Accounting Config is foundational to how Data Studio organizes data downstream. If the platform cannot reliably determine which period a file belongs to, records cannot be assigned to the correct close period and downstream products receive incorrect or unordered data.

Today, configuring Accounting Config for a dataset requires FloQast integrations team involvement — admins cannot do it themselves. Making this self-service, with a clear source-selection UI, is a prerequisite for Data Studio Beta.

The two source options reflect the two real-world patterns in the field:

* **Filename-based:** the accounting period is encoded in the filename (e.g., `Transactions_March_2026.csv`)
* **Column-based:** the accounting period is a value inside the file itself (e.g., a `period_end_date` column)

Both patterns exist in production today and both must be supported in the self-service flow.

---

## 🔐 Value Unlocked

Admins and implementation teams can configure Accounting Config themselves as part of the standard Add Dataset wizard — no integrations team involvement. The platform correctly identifies the accounting period for every incoming file from the moment the dataset is published.

---

## 🗝️ Key Examples

* **Example 1:** A client's GL file is named `Transactions_March_2026.csv`. The filename pattern step detected `month_name` and `year` tokens. In Accounting Config, the admin selects "From filename" and maps both tokens to the period. Every future file is automatically assigned to the correct close period by name.
* **Example 2:** A client's ERP exports a flat file where the period is not in the filename — instead, every row has a `period_end_date` column. The admin selects "From a column," picks `period_end_date`, and specifies the format (`YYYY-MM-DD`). The platform extracts month and year from that column on each load.
* **Example 3:** An admin is editing an existing dataset to switch from filename-based period identification to column-based. They open the dataset in Edit mode, navigate directly to the Accounting Config tab, make the change, and save — without stepping through the full wizard again.

---

## 💡 Key Benefits

* Admins configure Accounting Config without engineering or integrations team involvement
* Supports both real-world period-source patterns: filename tokens and column values
* Configuration is set once at the dataset level and applies automatically to every future file arrival
* Edit mode (tab navigation) allows targeted changes to Accounting Config without re-running the full wizard

## 🤔 Assumptions

**Established**

* Accounting Config covers period identification only. Entity identification is a separate step (Step 5) and is not part of Accounting Config.
* The "From filename" option is only available when the filename pattern step (Step 2) produced at least one time-related token (month, year, quarter, etc.). If no time tokens exist, "From a column" is the only available option.
* The "From a column" column picker is populated from the schema confirmed in Step 3. The column must exist in the schema.
* Accounting Config is set at the dataset level and applies to every file that matches the dataset's filename pattern.

**Open Items to Confirm**

* If a "From filename" config is set and a file arrives whose name does not produce a valid period extraction, how is the failure surfaced? (Likely needs a new error case in the Error Patterns PRD.)
* For "From a column," can a single file contain rows spanning multiple periods? If so, does the platform split them, reject the file, or assign all rows to one period?
* Does changing Accounting Config on a published dataset trigger a new dataset version?
* Should there be a sample extraction preview confirming correct period identification before the admin saves?

## 🗺️ Scope

### 🚗 In Scope

* Accounting period source selection: "From filename" (token mapping) or "From a column"
* Filename token mapping: admin maps one or more tokens from Step 2 to the accounting period (single token or combined)
* Column-based period: admin selects source column and specifies the column's period format
* Supported column formats: YYYY-MM-DD (extract month + year), Month name (e.g., January), YYYY-MM, Fiscal quarter (e.g., Q1 2026)
* Load behavior selection: Incremental, Full Replace, Append
* Accounting Config as Step 4 of the Add Dataset wizard
* Accounting Config as a directly-accessible tab in dataset Edit mode

### 🚦 Out of Scope

* Entity identification — handled in Step 5 (Entity Configuration)
* Multi-period file splitting (files containing rows for more than one period)
* Custom period formats beyond the four supported options
* Deduplication within Append load behavior
* Accounting Config for non-file-based connectors (API, CDC)

### APC1 — Configure Accounting Period from Filename Tokens

**User Story:** As an admin, I can map filename tokens to the accounting period so that the platform knows which close period each incoming file belongs to without reading the file contents.

**Importance:** High

**Details:** When the admin selects "From filename," the UI displays the tokens detected in Step 2 as read-only reference chips (e.g., `month_name`, `year`). The admin selects which token or combination of tokens represents the accounting period. If a single token encodes the full period (e.g., `YYYY-MM`), the admin selects it alone. If two tokens are needed (e.g., `month_name` + `year`), the admin selects the combined option.

**Notes:** "From filename" is only available if Step 2 produced at least one time-related token. If no time tokens exist, this option is unavailable and "From a column" is the default.

**AC-APC1-01 — Filename tokens shown as reference chips**

* Given I am on the Accounting Config step and select "From filename"
* When the panel renders
* Then the tokens identified in Step 2 are displayed as visual reference chips (e.g., month_name, year)
* And a selector allows me to choose which token(s) map to the accounting period

**AC-APC1-02 — Single token selection**

* Given I select a single token that encodes the full period (e.g., YYYY-MM)
* When I save Accounting Config
* Then the platform uses that token to extract the accounting period from each incoming filename

**AC-APC1-03 — Combined token selection**

* Given I select two tokens that together encode the period (e.g., month_name + year)
* When I save Accounting Config
* Then the platform combines those tokens to derive the accounting period (e.g., March + 2026 → March 2026)

**AC-APC1-04 — "From filename" unavailable when no time tokens exist**

* Given Step 2 produced no time-related tokens
* When I reach Accounting Config
* Then the "From filename" option is disabled or not shown
* And "From a column" is the only available selection

---

### APC2 — Configure Accounting Period from a Column

**User Story:** As an admin, I can designate a column inside the file as the source of the accounting period so that files whose names don't encode the period are still correctly assigned to a close period.

**Importance:** High

**Details:** When the admin selects "From a column," they pick the source column from a dropdown populated from the Step 3 schema, then select the format of the period value in that column.

**AC-APC2-01 — Column picker shows Step 3 schema columns**

* Given I select "From a column"
* When the column picker renders
* Then it shows all columns confirmed in the Step 3 schema

**AC-APC2-02 — Format selection is required**

* Given I have selected a column
* When I attempt to proceed without selecting a format
* Then the UI blocks progression and indicates format selection is required

**AC-APC2-03 — Supported format options are presented**

* Given I have selected a column
* When I open the format selector
* Then the following options are available:

    * YYYY-MM-DD (date column — extract month + year)
    * Month name (e.g. January, February)
    * YYYY-MM (year-month)
    * Fiscal quarter (e.g. Q1 2026)
    
---

### APC3 — Configure Load Behavior

**User Story:** As an admin, I can specify how records should be applied when a new file arrives for a period that already has data so that I have control over whether new files replace, extend, or append to existing records.

**Importance:** High

**Details:** Three options are presented as selectable cards. Load behavior is set at the dataset level and applies to every file that matches the dataset pattern.

**AC-APC3-01 — Three load behavior options are presented**

* Given I am on the Accounting Config step
* When the Load Behavior section renders
* Then three options are available:

    * Incremental: Add new records, preserve existing ones for the period
    * Full Replace: Replace all records for this period with the new file
    * Append: Always add records — never overwrite, even duplicates
    
**AC-APC3-02 — Selection required before proceeding**

* Given no load behavior is selected
* When I attempt to advance past Accounting Config
* Then the system blocks progression and indicates load behavior must be selected

**AC-APC3-03 — Selection persists in Edit mode**

* Given Accounting Config was saved with "Full Replace" as the load behavior
* When I open this dataset's Accounting Config tab in Edit mode
* Then "Full Replace" is shown as the current selection

## 😎 Future Considerations

* **Period extraction preview:** After configuration, show a sample extraction confirming how a real filename or column value would map to a period — e.g., "A file named `Transactions_March_2026.csv` would be assigned to period: March 2026."
* **Multi-period file support:** Some ERP exports contain rows spanning multiple periods within a single file. Splitting or flagging these is out of scope for v1.
* **Custom period formats:** Support for non-standard formats (fiscal period codes, Julian dates) beyond the four supported options.
* **Load behavior change impact analysis:** When load behavior changes on a published dataset, surface an analysis of how existing period data would be affected.

## Objective

This document defines the detailed requirements for establishing, managing, and monitoring QuickBooks Online (QBO) connections within the FloQast Data Platform and Data Studio. It covers both supported connection types — Direct API (OAuth 2.0) and FloQast-managed Fivetran — along with the Data Studio UI surfaces, credential storage, logging, and endpoint/table library experiences associated with each.

## Key Benefits

1. Flexible connection types: customers can connect via API for standard data needs or via FloQast-managed Fivetran for richer transaction-level data, with no Fivetran account required.
2. CAS-ready multi-entity management: realmId capture and a searchable, scrollable Connections tab allow CAS firms to manage dozens of client connections efficiently.
3. Secure, reusable credentials: tokens and connector credentials are encrypted, stored, and automatically refreshed so users authorize once and FloQast handles the rest.
4. Proactive error surfacing: connection errors and credential failures are visible immediately in Data Studio with actionable resolution steps, not buried in logs.

## Use Cases

* Creating a Direct API Connection  
  An admin opens the Data Studio Connections tab, clicks "New Connection" and selects QuickBooks Online (basic). They complete the OAuth 2.0 authorization in the Intuit consent screen. FloQast captures the realmId from the OAuth callback, stores the encrypted tokens, runs a validation call, and confirms the connection is active. The admin names the connection and associates it with a FloQast entity.
* Creating a Fivetran Connection  
  An admin selects QuickBooks Online (advanced) as the connection type. FloQast provisions the Fivetran connector on their behalf -  the admin provides the credentials through the connect card. FloQast triggers an initial sync to validate. The admin sees the connection appear as active in the Connections tab with QBO advanced listed as the source type.
* CAS Firm Managing Multiple Connections  
  A CAS firm administrator has 30+ client entities, each with its own QBO company and realmId. They use the search bar in the Connections tab to filter by client name or realmId. They scroll continuously through the list without pagination interruptions. Connection status badges make it immediately clear which clients have active, degraded, or broken connections.
* Diagnosing a Connection Error  
  A sync fails due to an expired OAuth token. The connection in Data Studio shows an Error status badge with the message "OAuth token expired" and a "Reconnect" button inline. The admin clicks Reconnect, re-authorizes, and the connection status returns to Connected. The failure is captured in the connection log with a credential error code.
* Browsing and Activating an Endpoint  
  A power user opens an API connection's detail view and navigates to the Endpoint Library tab. They browse available QBO REST API endpoints, find the custom fields endpoint, review its description and required scopes, and activate it. FloQast adds it to the connection's active endpoint list and begins pulling that data on the next sync.

| Goal | Metric |
| --- | --- |
| OAuth connection setup success rate | 99% |
| Time to create a connection | Less than 5 minutes |
| Error surfacing time | Less than 5 minutes after failure |

## Assumptions

1. realmId is returned as part of the OAuth 2.0 callback from Intuit and can be auto-captured by FloQast without requiring manual user input. This will be validated during technical discovery.
2. Credential encryption leverages FloQast's existing secrets management infrastructure.

## User interaction and design

  
Prototype of design: [https://www.figma.com/make/bY7CfAeSVx8duko8pXuat9/QBO-Connection-Needs?t=LROJrn7d5ZxHTCp2-1](https://www.figma.com/make/bY7CfAeSVx8duko8pXuat9/QBO-Connection-Needs?t=LROJrn7d5ZxHTCp2-1)

### **Connections Tab — List View**

The Connections tab is the primary surface for connection management in Data Studio. It replaces paged navigation with continuous scroll and introduces search.

‌

* Layout: Vertically scrollable list of connection rows. Load-on-scroll behavior with infinite scroll.
* Search bar: Persistent at the top of the list. Filters in real time as the user types. Matches against connection name, and associated entity name. Displays a "No results" empty state when no matches are found.
* Connection row fields: Connection name, Source type badge (QBO Basic / QBO Enhanced), associated entity/entities, status badge, last sync time.
* Status badges: Color-coded. Connected (green), Connecting (blue), Error (red), Paused (gray), Syncing (green). Error badges include a short inline message.
* Actions: Each row has a context menu or action row with: Edit, Pause/Resume, Reconnect (if applicable), View Detail.
* Language: All instances of "File" replaced with "Source" throughout this tab and any connection-related UI.

### **New Connection Flow**

#### **Step 1:  Select Source Type**

User clicks "Add Connector." A modal or page presents the connection type selection:

* QuickBooks Online Basic: Described as "Standard connection via QBO REST API. Best for Accounts and Balances."
* QuickBooks Online Enhanced: Described as "FloQast-managed connector for full transaction data. Needed for Transactions and expanded data models."
* sFTP remains as an available option as well

#### **Step 2a: Basic Setup Flow**

* User enters connection name
* User clicks "Connect to QuickBooks Online." Intuit OAuth consent screen opens in a new window or redirect.
* On successful authorization, FloQast captures the realmId from the callback and stores the encrypted access and refresh tokens
* System runs validation: test call to /companyinfo/{realmId}. Success shows a green confirmation and proceeds. Failure surfaces an error with a retry option.
* User selects to use a standard data setup or build my own setup

    * If standard data setup, they indicate what FQ entity the data is for
    

#### **Step 2b: Enhanced Setup Flow**

* User enters connection name
* Need to determine if the user can simply enter credentials (preferred) or must use a Connect Card to connect to Fivetran; see open questions
* 
* User clicks "Provision Connection." FloQast calls the Fivetran Management API to create the connector. Status shows "Provisioning" while this completes.
* System runs validation: triggers a Fivetran test sync. Success transitions status to Connected. Failure surfaces an error with detail.

#### **Step 3: Data Model Selection**

Presented after successful validation for both connection types. User enables or disables data models. Defaults: Accounts and Balances on; all others opt-in. (Handled by the Data Models child spec; referenced here for flow completeness.)

### **Connection Detail View**

Accessible by clicking a connection from the list. Contains:

* Source Data: Endpoint Name, Endpoint URL, Sync Frequency, Status, Last Synced, Associated Models (lineages)
* Actions: Options to: 

    * Edit - Opens modal edit for name and URL. 
    * Reconnect button visible when status is Paused or Error
    * Sync now option to sync data on demand
    * Pause - pauses syncing of data
    
* Sync Log tab: Table of recent sync activity. Columns: timestamp, data object, status (Success / Error), record count, error code (if applicable). Default view: last 30 days. Filterable by status and date range. Broader date range can be exported
* Add Data button (where "Add Files" is currently) - allows a user to add an endpoint to retrieve data; required endpoint name, path, sample data, and query parameters

    * When data source if Fivetran, a library of tables from Fivetran is displayed, including the table name and an expandable column list
    

### **Table Library (Fivetran Connections)**

* Accessible from the Add Data button within the connection detail view.
* Displays all QBO tables available in the FloQast-managed Fivetran connector schema. Each entry: table name, columns list (expandable), activation status toggle.
* Search and filter: by table name or source object.

### **Error States**

* Token expired: Status = Error. Inline message: "OAuth token expired. Reconnect to resume syncing." Action: Reconnect button.
* Invalid token / permission denied: Status = Error. Inline message: "Authorization error. Reconnect and verify QBO permissions." Action: Reconnect button + link to sync log.
* Fivetran connector error: Status = Error. Inline message: "Connector error. FloQast is investigating." Action: Link to error detail in sync log. FloQast internal alert triggered.
* Validation failure on setup: Inline error below the validation step with error code and a plain-language description. Retry button available. Connection is not saved until validation passes.
* Rate limit hit: Status = Warning. Inline message: "QBO API rate limit reached. Sync will resume automatically." No customer action required.

## Out of Scope

* Write-back to QBO: Connection is read-only. No requirements here govern writing data back to QBO.
* Customer-managed Fivetran accounts: Customers do not configure or access Fivetran directly. All Fivetran management is internal to FloQast.
* Non-QBO connections: This spec covers QBO only. Other ERP/accounting integrations are governed by separate connection specs.
* Real-time / webhook-based connection triggers: v1 is scheduled batch only. Event-driven ingestion is a future consideration.

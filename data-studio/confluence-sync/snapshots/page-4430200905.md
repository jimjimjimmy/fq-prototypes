## Objective

Integrate QuickBooks Online (QBO) into the FloQast Data Platform to enable reliable, normalized ingestion of QBO financial data across the close management, reconciliation, and reporting surfaces. This integration establishes a scalable connection layer that supports both standard and extensible data models, serves CAS firms managing multiple client entities, and provides two managed ingestion paths — direct QBO API and a FloQast-operated Fivetran connector.

## Key Benefits

1. Expanded data coverage — moves beyond Accounts and Balances to include GL Transactions, FX Rates, and Companies, enabling reconciliation and multi-currency close workflows.
2. CAS firm support — multi-realmId connection management allows CAS firms to manage all client entities from a single FloQast account with proper data isolation.
3. Customer-controlled data selection — customers choose which data models to activate, reducing ingestion overhead and supporting phased rollouts.
4. Extensibility via Data Studio — customers can configure additional QBO API endpoints and map custom fields without engineering involvement.

## Use Cases

* Standard SMB / Mid-Market Customer  
  A single-entity customer connects their QBO company to FloQast, enables Accounts and Balances for their close workflow. They use Data Studio to add a custom field their team tracks in QBO but that isn't part of the standard model.
* CAS Firm  
  A CAS firm manages accounting for multiple client companies, each with a distinct QBO Company Realm ID (realmId). The firm's FloQast administrator connects each client realmId as an independent entity, manages connection health across all clients from a centralized admin view, and ensures client data is strictly isolated. The realmId is the foundational identifier scoping all API calls and data to the correct client.
* Multi-Currency Close  
  A customer operating across multiple currencies activates GL Transactions and FX Rates. FloQast ingests both local and functional currency amounts with the applied exchange rate, enabling accurate period-end close and balance sheet reconciliation across currencies.
* High-Volume / Detailed Transaction Data (Fivetran)  
  A customer requires full GL transaction history that is available through Fivetran's incremental replication. FloQast provisions and operates the Fivetran connector; the customer has no Fivetran account or configuration responsibilities.
* Extended Data via Data Studio  
  A customer's implementation requires a non-standard QBO API endpoint (e.g., custom fields, attachments). A power user or FloQast implementation team member uses Data Studio to browse the endpoint library, map response fields to FloQast data model fields, previews a live sample, and activates the endpoint — without opening a support ticket or waiting for an engineering sprint.

## Assumptions

1. QBO REST API v3 remains the stable, supported API surface for the duration of this project. FloQast will monitor Intuit's developer communications for deprecation notices.
2. Intuit's OAuth 2.0 token lifecycle (180-day inactivity expiration) does not change materially during development.
3. QBO API rate limits remain at approximately 500 requests/minute per realmId; architecture must be designed to accommodate this constraint at scale.

## Notes on existing QBO integration:

  
We bring in data from the GL-QBO lambda (through the GL-SDK) and through wwwclose  
Some customers are on GL-SDK and others on wwwclose  
  
For CAS customers, we need both a key for which QBO instance to use for the end customer as well as the QBO credentials for the CAS customers' QBO access point.

50% of our QBO API requests go to reports/trialbalance endpoint  
48% of our QBO API requests to QBO go to the query/accounts endpoint  
  
At a high level, we read the trial balance rows, find the debit and credit columns, then subtract the credits from the debits to get the balance.  
We simply use the account id  
  
We fetch data when data is asked for. Typical use cases in Close would include recs refresh and completeness reports.  
We aren't sure if retained earnings is working effectively in QBO.  
  
If we were to take the Fivetran approach, we would need to handle refresh syncing.  
  
We would also need to understand the implications of more API calls to our partnership levels - we are currently at ~500k calls a month and have a partnership threshold at 1M calls a month. Fivetran could significantly impact this.

## Out of Scope

* Write-back / bi-directional sync: FloQast will not push data back to QBO in v1. Read-only ingestion only.
* QBO Desktop: This integration targets QBO Online only. QBO Desktop has a different API surface and is not covered.
* ERP integrations: This PRD covers QBO only. Other ERP/accounting system integrations (Workday, SAP, Yardi, etc.) are governed by separate PRDs.

## 1. Overview

This sub-PRD defines how data retrieved from the Sage Intacct XML API is mapped to FloQast's (FQ) canonical models for accounts, balances, dimensions, and reporting periods. All mapping logic is grounded in the current implementation in `parser.ts`, `balance.ts`, and `index.ts`.

For details on how API requests are constructed and how location hierarchy is used to nest company requests, see **Sub-PRD 9 — Request Construction**.

> **Terminology note:** "Location" refers to Intacct's organizational unit concept (`LOCATIONID`). "FQ entity" refers to FloQast's internal entity concept, assigned at the connection level. These are distinct concepts. FQ entity assignment is covered in Sub-PRD 2.

## 2. Account Mapping

Accounts are retrieved from Intacct via the `glaccount` object using `readByQuery`. The following table shows how each Intacct field maps to the FQ canonical account model:

| Intacct Field | FQ Canonical Field | Notes |
| --- | --- | --- |
| `ACCOUNTNO` | `internalId`, `number` | Used for both internal ID and display number |
| `TITLE` | `name` |  |
| `STATUS` | `active` | Value `active` → `true`; all other values → `false` |
| `CATEGORY` | `type` (Account Type) | Must be normalized to FQ Account Type enum. See Section 3. |
| `ACCOUNTTYPE` | `financialStatement` | Passed through as-is from Intacct |
| `NORMALBALANCE` | `normalBalance` | Passed through as-is from Intacct |

## 3. Account Type Normalization (CATEGORY → FQ Account Type)

The Intacct `CATEGORY` field is a broad account classification. It must be normalized to the FQ Account Type enum before being stored in FQ canonical models. The target enum values are:

* Asset

* Liability

* Equity

* Expense

* Revenue

Currently, `CATEGORY` is passed through without transformation in `parser.ts`. Normalization logic must be added. The mapping from Intacct `CATEGORY` string values to FQ Account Type enum values needs to be confirmed with Engineering.

> **Open Question:** What are the exact string values returned by Intacct for the `CATEGORY` field? Engineering to confirm the full set of possible values so the normalization map can be defined. Until confirmed, Account Type cannot be reliably set from Intacct data.

## 4. Balance Mapping

Balances are retrieved using the `get_trialbalance` XML function (not raw transaction queries). This returns pre-aggregated debit, credit, and adjustment figures per account per period.

### 4.1 Balance Field Mapping

| Intacct Field | FQ Canonical Field | Notes |
| --- | --- | --- |
| `endbalance` | `balance` | Period-end balance |
| Derived | `activity` | Computed as: `debits + adjdebits - credits - adjcredits` |
| `currency` | `currency` | ISO currency code |
| `glaccountno` | `number` | Account number cross-reference |

### 4.2 Reporting Period Mapping

Intacct reporting periods are retrieved from the `reportingperiod` object and mapped to FQ period fields. The FQ period model supports month, quarter, and year granularity. Intacct period data is parsed in `parser.ts` and matched to the corresponding FQ period record for each balance row.

| Intacct Source | FQ Period Field | Notes |
| --- | --- | --- |
| `reportingperiod` object | Period (month / quarter / year) | Matched to FQ period model by start/end dates |

## 5. Standard Dimensions

The following dimensions are supported for Intacct balance queries. Dimensions filter or segment the `get_trialbalance` request and are reflected in the balance data returned.

| Dimension | Intacct Source | Notes |
| --- | --- | --- |
| Reporting Book | `gcbook` / `useradjbook` | Identifies which general ledger book the balance comes from |
| Location | `location` (`LOCATIONID`) | Intacct's organizational unit; supports parent-child hierarchy (see Sub-PRD 9) |
| Department | `department` | Optional filter on balance query |
| Vendor | `vendor` | Optional filter on balance query |

## 6. Standard Custom Fields

The following custom fields are available on Intacct connections to configure how balance queries are constructed. These fields drive the parameters passed to `get_trialbalance`.

| Custom Field | Type | Default Value | Description |
| --- | --- | --- | --- |
| Include Reporting Book | Boolean | true | Whether to include reporting book data in balance queries |
| Reporting Book | String (dropdown) | Default reporting book for the connection | The primary `gcbook` used for balance retrieval; set during connection setup |
| Location | String | (none) | Intacct `LOCATIONID` to filter balance queries; if blank, queries all locations |
| Include Child Locations | Boolean | true | When a Location is specified, also include all child locations in the hierarchy (driven by `loc_subs` parameter in `get_trialbalance`) |
| Department | String | (none) | Optional department filter for balance queries |
| Vendor | String | (none) | Optional vendor filter for balance queries |
| Show Zero Balances | Boolean | true | Maps to `showzerobalances` parameter in `get_trialbalance`; when true, accounts with zero balances are included in results |

## 7. get_trialbalance Query Configuration

The table below shows how each custom field maps to the corresponding `get_trialbalance` API parameter, as implemented in `balance.ts`.

| Custom Field | API Parameter | Notes |
| --- | --- | --- |
| Reporting Book | `reportingbook` | Reporting book ID (`gcbook`) |
| Include Reporting Book | Adjustment books included | Adjustment book IDs constructed by appending reporting book ID to each adjustment book (e.g., `CASH` + `ACCRUAL` = `CASHACCRUAL`) |
| Location | `locationid` | Intacct location filter; blank = all locations |
| Include Child Locations | `loc_subs` | When true, child location IDs are recursively resolved and included via `addChildEntityIdsToIds` |
| Department | `departmentid` | Optional |
| Vendor | `vendorid` | Optional |
| Show Zero Balances | `showzerobalances` | Hardcoded default: `true` |

Additional hardcoded defaults on `get_trialbalance`:

* `showdeptdetail` = false

* `showlocdetail` = false

## 8. Books

Intacct supports two types of books:

* **Reporting books** (`gcbook`): The primary general ledger book used for balance retrieval.

* **Adjustment books** (`useradjbook`): Secondary books for adjustment entries. Adjustment book IDs are constructed by appending the adjustment book ID to the reporting book ID (e.g., reporting book `CASH` + adjustment book `ACCRUAL` = `CASHACCRUAL`).

All Intacct connections default to `multiBook: true`. Book IDs are assembled as a CSV string via `createBookIdsCsv` in `index.ts`.

## 9. Additional Hardcoded Connection Defaults

The following flags are hardcoded to `true` on all Intacct connections:

* `multiSubsidiary: true`

* `multiCurrency: true`

* `multiBook: true`
